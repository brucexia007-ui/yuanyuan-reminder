# 私人素材工程交付清单

复制到被 Git 忽略的 `work/<任务>/source-project/` 后填写。独立于 `.yuanyuan-pet` 交付；不要把填写结果提交 GitHub。路径只写工程内相对路径；照片引用使用无个人信息的素材标识，不记录本机绝对路径。

| 项目 | 相对路径或状态 | 指纹/版本/许可与缺项说明 |
| --- | --- | --- |
| 已确认主形象与确认记录 | 待填写 | 是否沿用；若改变，记录重新确认 |
| 可获得的高清完整动作源图 | 待填写 | 逐行动作清单；缺失明确标缺，不假称可完整重建 |

| 装配参数 | 待填写 | 每格192×208、整行映射、缩小/定位参数及来源 |
| 工具及源码版本 | 待填写 | 仓库地址/提交、Node/Rust/Python/Pillow、生成工具及可获得的模型版本 |
| 素材许可 | 待填写 | 来源与使用授权；许可文件副本 |
| 验收与修复记录 | 待填写 | 结构/范围/视觉/身份/原生分别列结果、待办和证据 |
| 最终宠物包 | 待填写 | SHA-256、实际验收应用版本 |

交付前逐项检查：

- 默认排除原始照片、EXIF、私人绝对路径、会话/聊天记录、应用缓存与数据库等应用数据。
- 原照和照片对照只留原私有任务目录，不复制进默认交付工程；需要额外交付原照时必须由用户明确指定范围。
- 检查文本中的路径及图像元数据；只归档已知来源的必要素材，不执行来源归档里的脚本。
- 工程不含密钥、自动收集的个人信息或安装目录副本。
- 旧包没有高清源图/主形象时写“不可获得”；可提取运行时图集，但不能标为高清源图。
- 未完成视觉或原生验收保持候选；原生记录绑定最终包 SHA-256 和应用版本，包变更后重新验收。
