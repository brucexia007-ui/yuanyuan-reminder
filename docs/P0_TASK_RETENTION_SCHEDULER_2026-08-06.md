# P0 任务事件长期清理调度证据（2026-08-06）

## 结论

任务守望数据库已有的7/90/180/365天有界清理现已接入常驻生命周期，不再只在启动后执行一次：

- 任务管道和控制管道都健康后才启动维护线程；
- 首轮延迟5秒，避免与启动、暂存重放和健康协商争抢；
- 此后每6小时低频重复，使用独立数据库连接；
- 每轮仍沿用最多1,000个事件、250个任务及同事务nonce清理边界；
- 全新AI库从建表前启用增量回收；每个发生删除的周期随后逐页推进、最多256页，无进展立即停止；
- 既有库与未知v0外部表不做隐式全库重写；
- 单轮打开、锁定或清理失败不会退出服务，也不会取消下一轮；
- 优雅退出会唤醒等待中的线程并完成回收，不留下后台维护任务；
- `--once` 与调试协议兼容进程不启动长期维护。

该能力只负责任务守望独立数据库，不触碰提醒数据库、记忆、安抚偏好、备份或用户正文，也不会生成猫咪提醒。

## 自动化证据

- 调度可在首轮到达前停止，清理次数为0；
- 首轮注入失败后仍会进入第二轮；
- 零重复周期被拒绝，不形成忙循环；
- 真实 `yuanyuan-ai.exe` 在5秒首轮之前已可响应健康检查并可立即退出；
- 真实子进程从含一条8天旧进度事件和一条最新事件的数据库启动，首轮只删除旧事件；
- 清理完成后控制管道仍健康，随后优雅退出成功；
- 数据层原有测试继续覆盖最新事件豁免、优先事件90天、批次收敛、nonce同步清理及故障整体回滚。
- 一年等价负载进一步覆盖3,650任务、175,200事件、7,300 nonce、118个删除周期和新旧压缩策略对照，见`P0_TASK_RETENTION_LOAD_QA_2026-08-06.md`。
