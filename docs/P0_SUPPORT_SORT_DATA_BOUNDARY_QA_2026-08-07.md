# P0 “理一理”数据去向与重新授权原型验收（2026-08-07）

## 结论

P0-065 的交互与数据边界原型已经完成：用户必须先选择“仅在本机整理”或“交给云服务整理”，看清本次数据流并明确勾选后，才能取得五分钟内最多使用一次的授权回执。切换去向、Provider 身份变化、过期、使用一次或取消都会令旧授权失效。

开发原型没有正文输入框、Provider 调用、网络、Tauri命令、存储、日志或分析能力；它只验证交互顺序。`yuanyuan-ai` 同时新增真正的 Rust 内存单次授权核心和授权后固定请求层：只有与可信Rust描述绑定的适配器才能在消费授权后收到本次用户原文。当前只用内存回环适配器验证边界，尚未注册生产命令或连接真实 Provider。专业复核、真实地区资源与 Core Provider 质量门完成前，正式 Support Box 和“理一理”入口继续关闭。

## 产品表达

- 圆圆只在整理板旁安静守着，并在用户选择去向时拨动一次实体去向牌；
- “本机/云端”、数据类别、排除项、保留政策和授权按钮属于独立工具界面，不使用猫咪对白气泡；
- 授权前不出现正文输入框，避免用户先写下敏感内容后才发现数据去向；
- 未来结果固定为“事实、感受、可控、下一步”四格整理板，但本原型不生成结果、不诊断情绪，也不声称安抚疗效。

## 冻结规则

协议见 `protocol/SUPPORT_SORT_DATA_BOUNDARY_V1.md`。单次回执只包含：

- 固定用途 `structure_fact_feeling_control_next_step`；
- 固定内容类别 `user_entered_text`；
- 本机/云端固定去向；
- Provider 不透明身份与64位十六进制指纹；
- 披露版本、签发时间、五分钟到期时间和 `oneUse=true`。

回执与状态机均没有用户正文、整理结果、情绪判断、任务身份或工作区字段。不可用、非法身份或非法指纹在授权前关闭失败；发送前 Provider 不一致也会拒绝并要求重新授权。

Rust核心使用随机不透明UUID令牌，只在AI进程内存中保存Provider绑定与到期时间；最多保留64项，签发新能力前清理过期项。消费会先移除令牌，再验证时间窗口和当前Provider，因此过期、时钟回退、身份变化和重放都不能恢复旧权限。取消可删除单项，断开/关闭路径可一次撤销全部；没有数据库、日志、备份或诊断写入接口。

固定请求层不接受任务、历史、记忆、文件、工作区或剪贴板参数。它在本机拒绝空白、超过16 KiB、包含NUL或Unicode双向格式控制符的正文；校验通过后才消费授权，并只构造 `schema_version`、固定内容类别和未经扩展的 `user_entered_text`。授权令牌和Provider身份/指纹不会发给适配器。Provider身份由字段私有的Rust描述对象和适配器成对注册；未来生产命令必须从Rust可信配置选择描述对象，不得从前端提交载荷构造。适配器启动失败后授权同样失效。

适配器终稿还要通过专用结果门：只接受精确 `present_information + normal` 意图、固定“模型推断/未知置信度/敏感”元数据，以及唯一一行“事实、感受、可控、下一步”四列表格；引用和模型动作必须为空。通过后只返回四个工具字段与可选用量，不把通用响应意图或显示文档外壳暴露给猫咪表达层。缺文档、普通陪伴意图、正式决策意图、错误Schema、降低敏感级别、改变四格或附加引用全部关闭失败。
