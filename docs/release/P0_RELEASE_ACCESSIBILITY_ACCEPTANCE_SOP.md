# P0 发布候选无障碍人工验收 SOP

## 目的

本流程用于关闭圆圆提醒正式发布候选的多档 DPI、Windows 文本缩放、高对比度、减少动态、全键盘、Windows Narrator 以及安装/卸载辅助功能门。程序化 DOM、CSS、UI Automation 或截图检查只能辅助定位问题，不能替代具名人工看到焦点、完成操作并实际听到 Narrator 输出。

## 前置条件

1. 只使用 `release-accessibility-acceptance-packet.json` 中列出的三项最终候选；三项 Authenticode 状态必须为 `Valid`，发布者必须与冻结策略精确一致并使用同一证书和可信时间戳。
2. 使用可回退的干净 Windows 测试快照和非敏感测试数据。不得读取或覆盖现有用户数据库、备份、浏览器资料或桌面内容。
3. 测试桌面必须为真实交互式 Windows 会话，Narrator 音频可由具名测试人听到。远程自动截图、无头浏览器、合成无障碍树或 AI 判断不能作为主要结论。
4. 每次候选字节、WebView2、Windows 构建、发布策略或验收脚本发生变化，都要重新生成验收包并重做受影响矩阵。

## 候选与环境记录

1. 运行 `npm.cmd run release:accessibility:packet:check`，记录包、发布清单和三项候选 SHA-256。
2. 从最终安装包完成一次干净安装，核对安装后的主程序哈希与包内 `nsis_installed_core` 完全一致。
3. 单独启动便携主程序完成启动、打开面板和完整退出烟测。
4. 记录非敏感机器别名、Windows 版本/构建、WebView2 版本、账户类型、系统语言、可回退快照哈希和验收起止时间。

## 视觉矩阵

在每一档设置下完成包中全部七条核心流程，并为每档至少保留一份候选绑定的结果记录。截图只能使用中性测试数据和背景。

1. Windows 显示缩放：100%、125%、150%、200%。
2. Windows 文本大小：100%、150%、200%。
3. Windows 对比度主题：至少一个深色主题和一个浅色主题。
4. 关闭 Windows 动画效果并开启应用减少动态设置。

每档必须确认：没有裁切、遮挡或意外横向滚动；正文可读；选中、禁用、错误和焦点状态可区分；信息不只依赖颜色；减少动态后状态含义仍完整且无闪烁。

## 全键盘路径

完全不使用鼠标、触控或 UI Automation 执行以下路径：

1. 面板主导航；
2. 提醒创建、编辑、停用、启用和软删除；
3. 备份与恢复确认；
4. 基础陪伴路径的开始、取消和退出；
5. 从宠物进入面板并完全退出程序。

每条路径都要确认所有控件可达、顺序合乎界面结构、焦点始终可见、对话框关闭后焦点返回来源、取消或退出入口明确可用。

## Narrator 人工听读

由记录中的具名人工测试人开启 Windows Narrator，并实际听取以下路径：

1. 面板地标和主导航；
2. 提醒管理状态、校验错误和操作结果；
3. 专注计时与动态状态；
4. 备份、恢复和破坏性确认；
5. 基础陪伴控件与随时退出；
6. 宠物当前状态和进入面板的入口。

必须听到准确名称、角色、状态和关键动态变化；不得存在导致任务无法继续的静默、重复阻塞播报或仅靠视觉才能理解的结果。Narrator 日志或自动无障碍树不能替代听读结论。

## 安装与卸载

使用最终安装包，以键盘和 Narrator 分别完成：安装、默认保留数据卸载、明确选择删除数据卸载。需要听清每个选择及其后果，焦点保持可见，并用隔离测试哨兵证明默认路径保留数据、显式选择后删除数据。不得对真实用户数据执行删除路径。

## 证据与签字

1. 每项观察至少引用一份 `docs/` 下的候选绑定结果或 HTTPS 证据；顶层至少两项引用，必须包含本 SOP。引用使用去重后的英文排序，不记录绝对路径、账户身份、真实数据库或其他敏感内容。
2. 从 `RELEASE_ACCESSIBILITY_ACCEPTANCE_ATTESTATION_V1.template.json` 创建实际 `RELEASE_ACCESSIBILITY_ACCEPTANCE_ATTESTATION_V1.json`。保持字段、矩阵顺序和固定路径 ID 不变，复制当前包中的字节数和哈希。
3. 只有具名人工测试人亲自完成全部结果、所有项均通过且未解决问题为零时，才能设置 `humanTester=true`、`humanObservedAllResults=true`、`automationUsedForPrimaryVerdict=false` 和各项 `passed=true`。
4. 将发布证据状态绑定到当前安装包哈希，加入验收包与实际签字两个引用，并且只在独立验证通过后把 `accessibilityAcceptanceVerified` 设置为 `true`。
5. 依次运行 `npm.cmd run release:accessibility:verify`、`npm.cmd run release:preflight` 和 `npm.cmd run release:gate`。任一命令失败都不能发布。

## 关闭失败边界

缺少实际签字、使用未签名候选、发布者或证书不一致、矩阵缺档、AI/机器人充当测试人、把自动化当作主要结论、Narrator 未实际听到、安装/卸载未走键盘与读屏、存在未解决问题或只修改发布证据布尔值时，验收门必须保持待处理或失败。
