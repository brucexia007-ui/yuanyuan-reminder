## 冻结与公开复核流程

只有 `main` 分支、工作区完全干净且具名维护者已复核发布范围时，才能执行冻结命令：

```powershell
npm.cmd run release:source-scope:test
npm.cmd run release:source-scope:verify
npm.cmd run release:unsigned-beta:test
npm.cmd run release:unsigned-beta:freeze -- `
  --confirmed-by "实际发布维护者" `
  --attest-release-scope-reviewed `
  --attest-unsigned-beta-only
npm.cmd run release:unsigned-beta:verify
```

源码范围门先要求当前提交基于 v1.3.2、位于干净 `main`，并排除 Learning Preview 目录、migration v12 和共享运行时代码中的学习标记；主数据库必须继续保持 schema 11。冻结命令随后重跑源码范围门、完整 `verify`、全量 `cargo test`、正式 Tauri/NSIS 构建和 NSIS 安装载荷复核，再把安装包、`SHA256SUMS.txt`、固定披露文案、发布策略、发布清单、源码范围策略/验证器/报告和冻结报告复制到不可覆盖的 `src-tauri/target/unsigned-beta/1.4.0/`。它会验证 PE 中不存在 Authenticode 证书表，并固定 `readyForGitHubPublish=false`；冻结本身不代表安全与人工证据已完成。

完成候选绑定的安全与人工复核并由人创建 GitHub prerelease 后，执行：

```powershell
npm.cmd run release:unsigned-beta:github:capture
npm.cmd run release:unsigned-beta:github:verify
```

公开复核只做匿名 HTTPS GET，要求标签精确指向冻结提交、发布状态为 prerelease、正文与冻结披露逐字一致、资产恰好为安装包和 `SHA256SUMS.txt`，并匿名下载两者逐字节复算 GitHub API digest 与本地 SHA-256。报告不可覆盖且始终保持 `stableRelease=false`。

## 发布时必须同时披露

- 标题或版本名称包含“测试版”或 `Beta`；
- 明确写明“此安装包未进行代码签名”；
- 同时附带 `V1.4.0_UNSIGNED_BETA_SHA256SUMS.txt`；
- 只通过项目官方 GitHub Releases 页面提供下载；
- 不得标记为稳定版，不得声称已通过正式发布门或不会触发 SmartScreen。

## Windows 校验命令

```powershell
Get-FileHash -Algorithm SHA256 ".\圆圆提醒_1.4.0_x64-setup.exe"
```

输出应与上表完整 SHA-256 一致；不一致时不要运行文件。
