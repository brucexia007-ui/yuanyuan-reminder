# v1.4.0 候选源码拆分审计

日期：2026-08-11
当前分支：`feat/learning-preview-foundation`
结论：Learning Preview 不属于 v1.4.0；当前工作区不能整体合入 `main` 或直接冻结。

## 决策依据

- `docs/V1.4.0_SCOPE_FREEZE_2026-08-10.md` 只允许发布阻断修复、回归修复、证据修正和不改变外部行为的维护；
- `docs/YUANYUAN_KAOYAN_ENGLISH_LEARNING_FINAL_PLAN.md` 明确学习模块只进入 v1.4.0 之后的新版本；
- `docs/LEARNING_PREVIEW_SCOPE.md` 明确当前学习实现默认关闭、仅作实验，不构成发布承诺；
- `V1.4.0_RELEASE_SOURCE_SCOPE_V1.json` 将上述决定固化为机器合同：v1.4.0 的发布提交不得包含学习目录、学习迁移或共享运行时代码中的学习标记，主数据库仍为 schema 11。

默认构建未打包学习代码是必要条件，但不能替代源码拆分。v1.4.0 的 `main` 发布提交本身也必须保持稳定范围，不允许先合入 Learning Preview 再仅依靠 feature gate 隐藏。

## 可作为 v1.4.0 稳定维护纳入的改动

以下工作与 Learning Preview 无关，可在独立复核后进入 v1.4.0：

- `PRIVACY.md`、Microsoft Store 接入文档、模板、脚本和匿名公开链接验证；
- 低成本未签名 NSIS 测试版的冻结、SHA-256、GitHub prerelease 匿名回读和来源范围门；
- “删除全部本地数据并退出”的 Windows 后端、设置页、测试和 Store 数据生命周期合成 QA；
- Store 候选、许可证、安全产品、WACK、运行、预提交和认证的关闭失败合同；
- 与上述发布边界相配套的 README、策略、进度和证据修正。

这些改动仍需从当前混合工作区提取，不能因为类别正确就视为已经形成发布提交。

## 安全提取顺序

1. 先由维护者保全当前功能分支的全部未提交工作，避免在拆分过程中丢失 Learning Preview；
2. 从当前 `main` 基线 `c2eca5e100def50ff255d6b77145b1cf35f3e0f8` 建立稳定维护工作区；
3. 先纳入整文件稳定改动，再逐个拆分上表混合文件；
4. 不复制当前 `Cargo.lock` 和 `THIRD_PARTY_LICENSES.txt`，而是在稳定依赖清单确定后重新生成并复核；
5. 运行 `npm.cmd run release:source-scope:verify`，要求干净 `main`、v1.3.2 祖先关系、排除路径、运行时标记和 schema 11 全部通过；
6. 再执行完整 `verify`、`cargo test`、Tauri 构建和无签名候选冻结；
7. 冻结前后提交或工作区有任何变化，都必须废弃本次结果并重新开始。

当前没有执行提交、暂存、分支切换、合并、推送或发布操作。
