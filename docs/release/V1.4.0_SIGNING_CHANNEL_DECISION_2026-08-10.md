# v1.4.0 签名与发布渠道决策包

状态：待项目负责人选择，尚未修改 `RELEASE_POLICY_V1.json`

日期：2026-08-10

候选安装包：`6F41A4B19BD0E8DFC21432CD23C893D17AFB5D2C5C9F42C632567E2BFD2D2225`

## 1. 必须先做这项决定的原因

发布渠道、精确发布者身份和时间戳服务尚未冻结。签名协议、外部信任、许可证人工复核、完整升级回退和最终无障碍矩阵都绑定最终签名候选；继续在未签名候选上补这些人工证据会在签名后因哈希变化全部失效。

当前 v1.4.0 冻结范围是直接分发的 Windows x64 NSIS 安装包与独立主程序。改变为 MSIX 属于新的安装、升级、数据迁移和卸载边界，不能把现有 NSIS 证据直接沿用过去。

## 2. 当前可选渠道

| 渠道 | 当前候选可沿用 | 费用与地区 | SmartScreen | 主要影响 |
| --- | --- | --- | --- | --- |
| Microsoft Store MSIX | 否，需要新候选 | Store 开发者新 onboarding 当前可免费注册；微软托管并重签 | Store 安装不出现下载型 SmartScreen 警告 | 需要新增 MSIX、身份、更新、数据迁移和与 NSIS 并存/切换设计 |
| Microsoft Store EXE/MSI | 部分 | 仍需自行购买受信 CA 证书并托管不可变版本 URL | Store 流程可信，但 EXE/MSI 仍须发布者签名 | 不能绕过当前 Authenticode 门，也没有 Store 托管更新 |
| Artifact Signing Public Trust | 是 | Basic 当前约 9.99 美元/月、每月 5,000 次；组织仅限美国、加拿大、欧盟和英国，个人仅限美国和加拿大 | 初期仍可能出现未知应用，信誉逐步积累 | 无硬件令牌，适合直接下载和自动化签名，但有身份地区限制 |
| 传统 CA OV 代码签名证书 | 是 | 微软当前比较页给出的典型成本约 150–300 美元/年，地区覆盖更广 | 与 Artifact Signing 一样需要积累信誉 | 最适合不满足 Artifact Signing 地区条件且必须保留 NSIS/便携版的发布者 |
| 传统 CA EV 代码签名证书 | 是 | 通常明显高于 OV | 自 2024 年起不再提供首次下载即时 SmartScreen 绕过 | 仅因企业采购或其他身份要求选择，不应为了 SmartScreen 溢价 |
| SignPath Foundation OSS | 理论上可签 EXE，但当前不应依赖 | 符合条件的开源项目免费，证书发布者为 SignPath Foundation | 使用受信代码签名证书，但仍受信誉与平台判断 | 当前安装包包含非 OSI、仅限个人非商业使用的圆圆素材，与其“所有组件采用 OSI 许可、无专有组件”条件冲突；申请也没有通过保证 |

## 3. 条件化建议

### A. 保持 v1.4.0 NSIS 与便携版，发布者位于中国或其他 Artifact Signing 不支持地区

建议选择 `ca_code_signing_certificate`，购买 OV 证书并以经验证的个人或组织法定名称签名。不要仅为 SmartScreen 购买 EV。此路径改动最小，可以复用当前安装、升级和卸载证据，但签名后三项正式产物哈希变化，所有候选绑定人工包必须重新生成和执行。

### B. 发布者满足 Artifact Signing Public Trust 地区与身份条件

建议选择 `artifact_signing_public_trust` Basic。先完成 Azure 计费资料与法定名称一致性、身份验证和证书配置，再把签名接入受控构建。不要承诺首次下载无 SmartScreen 提示。

### C. 预算必须为零，并接受延后当前 NSIS 正式发布

建议把 Microsoft Store MSIX 作为独立后续候选，而不是修改当前 v1.4.0 证据。先做 MSIX 技术刺探，验证托盘、开机启动、通知、单实例、WebView2、数据目录、备份恢复、升级和卸载选择，再决定是否以 Store 为主渠道。

### D. 申请 SignPath Foundation

只有在把圆圆图像、图标和截图更换为 OSI 兼容素材或取得满足其政策的重新许可，并补齐公开代码签名政策、MFA、作者/复核者/批准者角色及可验证构建后，才值得作为并行申请。它不应阻塞当前发布路径。

## 4. 负责人需要冻结的五个输入

1. `ownerType`：`individual` 或 `organization`；
2. `legalRegion`：法定个人或组织所在国家/地区；
3. `legalPublisherName`：准备接受身份验证并显示给用户的精确法定名称；
4. `distributionGoal`：`direct_download`、`store_msix` 或 `both`；
5. `annualSigningBudget`：可接受的年度签名与发布预算。

这些输入必须由人类负责人提供。不得从 Git 提交名、邮箱、时区、仓库名或 AI 推断法定身份与地区。

## 5. 选择后的工程动作

1. 更新 `RELEASE_POLICY_V1.json` 的 `selectedChannel`、`publisherSubject` 和 `timestampUrl`；
2. 固化签名工具、最小权限角色、凭据不落盘边界和 `/fd SHA256`、RFC 3161 `/tr`、`/td SHA256`；
3. 以冻结身份签署 Tauri 主程序、NSIS 实际安装主程序和安装包，并证明同证书；
4. 重新生成清单、SBOM、许可证包和全部候选绑定人工包；
5. 执行 Defender、SmartScreen、两款第三方安全产品、无障碍、真实旧库升级/中断/重启/回退和许可证具名复核；
6. 只有严格 `release:gate` 返回 0 后才允许发布。
