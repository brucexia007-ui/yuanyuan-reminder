# v1.4.0 MSIX 技术预览验证

状态：打包结构通过；本机未签名安装受环境限制；不可提交 Store、不可公开分发

日期：2026-08-10

## 1. 结论

已建立独立于现有 NSIS 的 Windows x64 MSIX 技术预览入口。它证明当前 Tauri 主程序可以被收敛到一个最小 MSIX 载荷，并通过 Windows SDK `MakeAppx` 的打包、解包和精确文件边界校验。

本次结果不把 MSIX 宣称为正式候选：包使用本地占位身份、保持未签名、尚未取得 Partner Center 身份，也没有完成应用启动、更新、迁移、自启动、通知、单实例、WebView2、用户数据或卸载行为验收。`storeSubmissionReady` 明确为 `false`。

## 3. 自动验证

以下验证已通过：

- `npm.cmd run msix:preview:build`：在独立 Cargo 目标目录构建主程序，并完成 MSIX 打包、解包和精确载荷校验；
- `npm.cmd run msix:preview:test`：2/2 通过，覆盖正确候选与身份、Store 就绪伪声明、载荷扩张、来源漂移等负向场景；
- `npm.cmd run msix:preview:verify`：重新计算候选、主程序、清单、构建脚本、图标和 MakeAppx 哈希，确认 `storeSubmissionReady=false`；
- `npm.cmd run msix:preview:build:reuse`：仅用于清单/打包脚本迭代，复用已经隔离构建的主程序，不得用于源码变化后的正式候选。

当前工作区仍有其他功能开发改动，源码冻结后必须执行完整 `msix:preview:build`，不得把本次技术包直接提升为提交候选。

## 4. 本机安装诊断

安装脚本按可回滚边界运行：管理员 PowerShell、`Add-AppxPackage -AllowUnsigned`、不启动应用、成功后立即卸载、不修改证书库和开发者模式。

本机 Windows 构建 `10.0.26200.7623` 在清单阶段返回 `0x80080204`，拒绝未签名 Publisher OID。为排除项目自定义名称问题，又使用微软文档中的原样 `CN=AppModelSamples, OID.2.25.311729368913984317654407730594956997722=1` 做隔离复现，结果相同。因此当前结论是“本机 AppX 部署层不接受该未签名测试机制”，不是“应用已安装后运行失败”。测试没有留下包注册，没有启动应用，也没有写入证书库或修改开发者模式。

微软文档说明，该 OID 与 `-AllowUnsigned` 仅用于 Windows 11 本地快速测试，不应用于广泛分发；正式发行仍应签名。项目保持现有低成本路线：GitHub Releases 只发布明确标注并附 SHA-256 的未签名 NSIS 测试版，正式稳定版使用 Microsoft Store 分配的身份和托管签名。

## 5. Store 前剩余工作

1. 在干净的受支持 Windows 11 虚拟机或实体机重新执行安装、启动、退出和卸载测试；
2. 验证托盘、开机启动、通知、单实例、WebView2、数据目录、备份恢复、NSIS 到 MSIX 迁移、更新和卸载选择；
3. 冻结源码与依赖后重新完整构建，并重新生成候选哈希和许可证证据；
4. 完成 Partner Center 账户、应用名称保留和 Store 分配的 `Name`、`Publisher`、`PublisherDisplayName`；
5. 用 Store 正式身份重建包并通过 Windows App Certification Kit、Partner Center 认证和商店安装回归；
6. 上述门全部通过后，才把 `RELEASE_POLICY_V1.json` 的 `selectedChannel` 从 `pending` 改为 `microsoft_store`。

正式链的身份模板、干净源码构建器、候选复核、隐私政策与 listing/截图/合规输入、一次性环境临时受信运行/WACK、十三项人工预提交矩阵和认证后 Microsoft 重签包最终回归入口已经准备完成，使用顺序与当前阻断项见 `MSIX_STORE_ONBOARDING_RUNBOOK.md`。这些入口当前会因 Partner Center 实际身份缺失和工作区未冻结而按设计退出，不改变本技术预览的 `storeSubmissionReady=false`。
