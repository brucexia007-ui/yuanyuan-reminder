# 用自己的宠物制作桌面提醒工具

需要从照片制作时，将[完整提示词](../AI_CUSTOMIZATION_PROMPT.md)、3–8 张有权使用的照片、名称与性格交给支持参考图生成或编辑、能处理本地文件的 Coding 工具或素材制作方。流程是**提供照片 → 确认主形象 → 制作并验收动作 → 导入宠物包**。工具负责从 https://github.com/brucexia007-ui/yuanyuan-reminder 核实来源，普通用户无需运行命令或编辑文件。主形象更换时需重新确认，其他制作步骤由工具自行检查推进。

默认采用摄影写实风格，用户也可明确指定其他风格。图片工具必须实际接收参考照片；仅有聊天或编程能力并不保证能生成保留宠物身份的图片。应用内目前不能直接上传照片自动生成。

## 只想改名或换已有形象（1.5.9 起）

打开“设置 → 我的宠物”，或从宠物右键菜单进入同名页面。不需要重新安装或开发工具：

1. 输入昵称并保存；每个形象分别记住名字，“使用原名”清除当前形象的昵称。
2. 点击“导入宠物包”，选择 `.yuanyuan-pet`，查看动作预览和许可说明，再确认加入。
3. 导入不自动切换；在列表中点“使用此形象”才会生效。
4. 仅闲置的导入形象可以移除；只删除应用本地副本及其昵称，原始文件不动。内置圆圆不能移除。
5. “恢复默认宠物”恢复内置圆圆及原名，保留其他形象和昵称。

切换不重启专注、学习、休息或提醒；正在玩的短互动会结束。缺少学习或装扮素材时使用该宠物自己的基础动作。预览不会记录照料或触发真实业务。

数据库备份保存选择和昵称，但不打包素材。换电脑或恢复后缺包会暂时显示内置圆圆，重新导入原包即可恢复；因此请保留原始 `.yuanyuan-pet` 文件。昵称不会替换提醒正文、学习内容、任务摘要或历史记录中的文字。所有日常操作在本机离线完成。

下面是**素材制作方**的开发流程；照片生成不是本次应用内功能。成品格式和打包命令见[宠物包规范](PET_PACK_SPEC.md)。

本教程适用于 Codex、Kimi Code 和其他能够读写本地项目的 Coding 工具。最终 Windows 程序完全独立运行，不需要保留 Coding 工具。

## 准备照片

建议提供 3–8 张清晰照片：

- 正脸和左右侧脸；
- 自然站立或坐姿的全身照；
- 能看清眼睛颜色、鼻子、耳朵和毛色的近照；
- 能看清背部、尾巴及标志性花纹的照片；
- 如果体态特殊，再补充俯视或趴卧照片。

照片最好光线自然、不过度美颜、没有衣服遮挡主体。只提供你有权使用的图片；公开仓库不应提交家庭环境、定位信息或含有他人的原始照片。

## 第一步：建立身份锁定说明（两条路线共用）

将 [身份锁模板](../pet-template/identity-lock.template.md) 和 [写实与动作验收模板](../pet-template/realism-review.template.md) 复制到被 Git 忽略的私人 `work/` 目录，写清：

- 宠物名称、品种与真实年龄感；
- 主毛色、渐层、毛流、细小杂毛、花纹分布和不对称特征；
- 脸型、眼睛颜色/大小/间距、口鼻长度、耳朵和鼻子的形状；
- 头身比例、身体胖瘦、四肢长度和尾巴；
- 身份照片与风格参考各自的作用，以及用户明确选择的风格；
- 必须保留与必须避免的特征。

这份说明是所有动作生成的视觉来源。任何一行发生品种、脸型、眼睛、毛色或体态漂移，都必须重做完整动作行。

## 第二步：确认主形象与试做代表动作

制作方先实际查看全部照片，以自然全身照为主要依据，保留真实形体，进行必要的背景去除或姿态整理。需要生成时，将原照作为实际图像参考输入。圆圆、饺饺仅参考毛发质感、写实程度与自然动作，不能把它们的脸、花纹或比例换到新宠物身上。

默认写实要求是自然毛流、胡须、眼部反光、一致的柔和光线和身体自身明暗；背景透明，无地面投影或外发光。避免为可爱而放大眼睛、缩短口鼻/四肢、幼态化、过度光滑的玩偶毛发或风格化 3D 吉祥物效果。照片里本来存在的圆眼、短鼻必须保留，不机械修成长脸小眼；用户主动指定卡通等风格时按该选择评审，并继续保持身份与动作一致。

1. 先制作一张完整身体主形象，展示原照私有对照、高分辨率图及接近桌面实际尺寸的预览。
2. 请用户确认身份与风格后再制作动作。无回复不视为确认；主形象失败时回到原照修正，不在失败图上不断衍生。
3. 确认后试做待机呼吸/眨眼、转头和行走，由制作方检查自然度、身份一致和连续播放，通过后再批量生成。
4. 每次生成实际传入原照和已确认主形象；动作漂移时重做相关完整动作行。更换已确认主形象必须重新确认，其他步骤无需重复询问。

待机以轻微呼吸、自然眨眼、耳朵和尾尖小幅活动为主；行走体现关节弯曲、落脚和重心转移。避免频繁歪头、拟人挤眼微笑和橡皮式拉伸，同时完整保留跳跃、提醒与互动语义。已有素材只有通过身份、所选风格及动作检查才可复用。若工具无法使用参考图或反复修正仍不能保持身份，报告具体限制，不自行改成卡通并宣称完成。

## 第三步：生成标准 8×11 图集

按照 [宠物包规范](PET_PACK_SPEC.md) 生成 9 行标准动作和 16 个注视方向。如果 Coding 环境提供 `hatch-pet` 能力，应优先使用它来准备、生成、验证和打包标准 v2 图集。

关键要求：

- 先通过主形象确认和三个代表动作检查，再批量生成；
- 每个动作行一次生成完整的连续帧；
- 向左移动只能在视觉上适合镜像时由向右行确定性镜像；
- 注视方向先确认上、右、下、左四个主方向，再插值完整 16 个方向；
- 最终标准图集必须是 `1536 × 2288` 的透明 WebP；先保留清晰源素材，再统一缩小装配，不要求模型一次画完全部大图集。

普通宠物包在被忽略的素材目录装配，避免覆盖内置资源，例如：

```text
work/my-pet/assets/spritesheet.webp
```

独立应用路线才将验收后的资源放到自己的工作副本 `public/assets/pet/`。

## 第四步：补齐睡眠和扩展互动

圆圆提醒还需要睡眠 3 行、生活互动 21 行。每行生成一张含 8 个连续动作的横向素材，再用项目脚本装配。

睡眠图集：

```powershell
python scripts/build_sleep_atlas.py `
  --enter path\to\sleep-enter.png `
  --loop path\to\sleep-loop.png `
  --output work\my-pet\assets\sleep-atlas.webp `
  --validation work\pet-qa\sleep-validation.json `
  --preview-dir work\pet-qa\sleep-previews
```

生活图集需要为 [21 个动作行](PET_PACK_SPEC.md#4-生活与互动图集-life-atlaswebp) 分别提供输入；同样输出到私人素材目录。按定制提示词补齐学习 4 行，情境装扮缺省时使用本宠物基础动作；协议可选组的完整性和回退规则见[成品包规范](PET_PACK_SPEC.md#9-应用内成品包-v1159-新增)。查看完整参数：

```powershell
python scripts/build_life_atlas.py --help
```

这些脚本需要 Pillow 和 NumPy：

```powershell
python -m pip install -r requirements-pet-tools.txt
```

## 第五步：验收与交付普通宠物包（默认）

制作方按[验收模板](../pet-template/realism-review.template.md) 分别记录主形象确认、结构检查、视觉复核和原生播放。逐行检查身份、所选风格、毛发/花纹闪烁、比例变化、基线和循环接缝，在深浅背景及实际桌面尺寸播放。用户确认只覆盖主形象，不代替完整动作验收。

按[离线打包说明](PET_PACK_SPEC.md#10-离线打包)准备 `pet-manifest.json`、图集、回退图和独立许可。制作方使用[普通宠物包内部入口](../customization/README.md#普通宠物包路线默认)锁定素材哈希并生成候选；该入口不会生成图片。确认原生导入、动作播放、互动、切换、重启及声明兼容版本后，交付 `.yuanyuan-pet`、校验和、许可和单独的验收报告。任何未验收项都保留为待办，不能把包生成成功写成写实或原生验收通过。

原照、私有对照、身份锁、主形象确认与填写后的 QA 记录只在私人工作目录保存，不放进宠物包或公开 GitHub。普通宠物包不改应用名称、图标或数据库，也不执行后面的独立应用构建与发布步骤。

## 独立应用路线（仅用户明确要求时）

继续使用前四步的身份与素材流程，但在独立工作副本内执行以下步骤。对应内部入口和恢复命令见[制作方合同](../customization/PET_CUSTOMIZATION_AGENT_PROMPT.zh-CN.md)。

### 更新名称、图标和应用身份

至少修改：

- `src-tauri/tauri.conf.json` 中的 `productName`、窗口标题和 `identifier`；
- `src-tauri/Cargo.toml` 中的包描述与作者；
- `package.json` 中的名称和描述；
- `README.md`、应用内文字和宠物显示名称；
- `src-tauri/icons/` 中的 Windows 图标。

`identifier` 必须唯一，例如 `com.yourname.yourpetreminder`。更改它会使用新的本地数据目录，避免与圆圆提醒共用数据库。

### 验证独立应用

```powershell
npm.cmd ci
npm.cmd run verify
cd src-tauri
cargo test
cd ..
npm.cmd run tauri build
```

还要人工检查：

- 100%、125%、150% 缩放；
- 单屏和多屏；
- 喝水、活动和普通事项重叠；
- 专注状态是否保持安静；
- 猫条视线、左右逗猫、摸头区域和扔球完整流程；
- 睡眠进入、循环和唤醒；
- 提醒气泡不遮住宠物脸。

### 发布独立应用版本

1. 移除圆圆素材并加入你自己的素材许可；
2. 修改应用名称、图标和 Windows 标识符；
3. 更新版本号和 `CHANGELOG.md`；
4. 推送 `vX.Y.Z` 标签，由 GitHub Actions 生成安装版、便携版和 SHA-256；
5. 在 Release 中说明这是独立分支，不是圆圆提醒官方版本。

可以直接使用仓库根目录的 [AI_CUSTOMIZATION_PROMPT.md](../AI_CUSTOMIZATION_PROMPT.md) 启动一次完整的 Coding 工具任务。
