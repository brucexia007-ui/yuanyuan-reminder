# Hook 配置写入事务 v1（内部原型）

日期：2026-08-04  
状态：接入、精确撤销、底层事务与官方目标封装已在临时目录验证；未接入 Tauri、设置页或真实 Codex / Claude 配置

## 1. 目的与边界

底层事务解决“用户已看过一个脱敏差异后，目标文件在确认期间没有变化，并且能够无损、可恢复地安装或撤销候选配置”这一小段问题。其上的官方目标封装只接收已授权的 `connector_id + source_instance`，由稳定核心重新读取信任状态、生成当前 Bridge 参数集合并解析唯一用户级根目录；确认时调用方只提交令牌。两层接口都不允许模型或 WebView 提供任意目标路径。当前仍不取得来源工具自身的 Hook 信任，也不安装 Bridge。

底层实现位于稳定核心私有模块 `src-tauri/src/connector_config_write.rs`，官方目标封装位于 `src-tauri/src/connector_config_official_write.rs`。两者都没有 Tauri command、前端调用或后台自动任务；当前只能由同一 Rust crate 的测试在临时目录调用。

## 2. 预览与确认契约

预览阶段先验证绝对路径、固定文件名、格式、普通父目录与 64 KiB 上限，再调用纯连接器库生成无损候选。需要改变时，最多保存 16 个待确认操作，每个操作使用随机 UUID 令牌并在两分钟后过期，绑定：

- 目标是否存在；
- 原始内容 SHA-256 与打开后 Windows 文件身份；
- 候选内容 SHA-256 与新增 handler 数量；
- 格式和内部预期 handler 规格。

对外预览只返回令牌、剩余秒数、数量及固定布尔事实，不返回路径、配置正文、命令、所有权身份或凭据引用。幂等的无需修改状态不生成令牌。

执行阶段先单次消费令牌，再重新验证路径、重读文件并比较存在性、摘要与文件身份；随后重建候选并比较候选摘要和数量。任一变化都返回固定错误并保持目标不变，令牌不能重放。

官方目标封装另签发一个不暴露底层令牌的两分钟单次令牌，绑定授权身份、当前预期 handler 集合、官方根目录，以及该工具所有用户级候选来源的存在性、SHA-256 和 Windows 文件身份。Codex 的 `hooks.json` 与 `config.toml` 作为一个来源集合处理；确认时即使只新增或替换非首选 `config.toml`，也会停止而不是继续写 `hooks.json`。Claude Code 当前集合为用户级 `settings.json`。授权密钥引用、Bridge 参数集合或官方根目录变化同样使确认失效。

撤销候选只接受语义所有权精确且原始节点字节仍等于圆圆规范序列化结果的 handler。圆圆新建根配置和插入既有配置时都使用相同的紧凑规范节点，从而可以在不存储配置正文的前提下复算节点摘要。规范单-handler组可以整组删除；混合组只删除规范 handler。注释、重格式化、额外字段、重复或意外圆圆条目全部进入人工复核。撤销后保留空事件数组/`hooks`容器，不猜测其是否由用户创建；保守残留优先于扩大删除范围。

## 3. 文件事务

- 目标只允许绝对路径下的 `hooks.json` / JSON 或 `settings.json` / JSON；TOML 和其他文件名关闭失败；
- 父目录和现有目标必须是普通对象且不是重解析点；路径检查后还使用打开句柄的文件属性和卷序列号/文件索引复核身份；
- 临时文件与备份在目标同目录以随机名创建，使用 `create_new`，写入并刷新后应用当前用户专用 DACL；
- 现有目标先创建带时间戳的精确字节备份，然后使用 `ReplaceFileW + REPLACEFILE_WRITE_THROUGH`；
- 缺失目标使用不带覆盖标志的 `MoveFileExW + MOVEFILE_WRITE_THROUGH`，确认后并发出现的文件不会被覆盖；
- 替换后重新核验目标摘要和文件身份；失败时只有确认目标仍是本次临时文件身份才允许恢复精确备份，清理也只针对本次捕获身份的文件；
- 任何错误都使用固定枚举，`Debug` 和序列化结果不包含路径、令牌、摘要、正文或底层系统错误。

## 4. 当前证据

普通测试覆盖：

1. 现有文件逐字保留、精确备份、成功替换和令牌单次消费；
2. 缺失文件原子创建且不产生备份；
3. 内容变化及“内容相同但文件已被替换”的并发拒绝；
4. 令牌过期和无需修改时不生成令牌；
5. 目标被占用导致替换失败时原文保持、临时文件和备份精确清理；
6. 非法时间发生在任何自有文件创建前；
7. 相对路径、错误文件名、TOML 和容量上限关闭失败；
8. 返回结构与错误调试输出脱敏。

官方目标封装另覆盖：生产接入/断开入口函数形状不接受路径、Codex 非首选来源在确认期间出现、授权材料/根目录变化、内联 Hook 冲突、连接—断开—重复断开、被触碰节点拒绝、16 项确认容量，以及预览/错误不回显路径或身份材料。

真实目录/文件重解析点用例需要 Windows 符号链接创建特权。当前环境返回系统错误 1314，因此该用例按设计忽略于普通测试，不能宣称通过；代码同时执行路径元数据与打开句柄属性两层拒绝，仍需在具备特权的发布环境复跑。

## 5. 正式入口门禁

1. Bridge 必须以受信签名身份进入安装、升级与回退矩阵，写入前还需完成 Codex `/hooks` 信任复核与 Claude `/hooks` 只读核验；
2. 设置页必须展示结构化差异、备份事实、影响范围和明确确认，取消或超时零写入；
3. 将已实现的私有断开组合状态机接入可恢复的用户界面；配置冲突不能阻止用户明确选择单独撤销认证权限，信任撤销也不能授权删除被修改的配置；
4. 明确项目级配置的显式授权与只读检查范围；未读取的项目来源不能被宣称已参与冲突判断；
5. 完成特权重解析点、锁占用、满盘/权限错误、安全软件干预、升级中断和卸载矩阵。

上述门禁完成前，产品只保留“只读检查 Hook 配置”，不显示写入、修复或断开按钮。
