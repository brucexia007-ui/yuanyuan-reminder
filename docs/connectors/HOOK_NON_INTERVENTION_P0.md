# P0 Hook非干预报告

更新时间：2026-08-04  
结论：官方格式/语义与库级契约通过；真实工具进程级验证待完成

## 已验证

- 解析层不访问网络、不调用模型、不迁移数据库、不等待界面；
- 输入硬上限为64 KiB，无效JSON、未知事件、缺失身份和未知版本都有确定性降级；
- Hook边界的固定结果为空标准输出、退出码0，与解析或后续投递结果无关；
- 权限请求只生成 `waiting_user` 观察事件，不产生 `allow`、`deny` 或任何反馈正文；
- 敏感字段不会进入统一事件；错误类型不包含原始载荷；
- 当前连接器库27项测试通过，其中13项覆盖单条目、多事件集合与多来源Hook配置只读所有权预览；
- Codex官方格式已冻结为`hooks.json`或`config.toml`内联`[hooks]`，Claude Code官方格式已冻结为`settings*.json`中的`hooks`对象；当前实现只读解析，不写配置；
- Claude `TaskCompleted` 不再读取官方Schema不存在的`status`字段；`StopFailure`只形成部分失败证据且丢弃错误正文；
- 真实Bridge调试进程已分别接收合成Codex与Claude原始载荷，从受控Credential Manager凭据取钥、生成随机nonce、签名并经安全命名管道送达；两条成功路径均为空stdout/stderr、退出码0且未创建暂存目录；接收载荷不含原提示词、目录、模型回复、工具输入输出或原始会话/任务ID；
- 原始载荷解析、凭据读取、签名、投递和必要时暂存已位于同一个3秒进程级看门狗内；缺失凭据路径在1秒目标内静默退出0。

## 尚未验证

- Codex/Claude Code真实Hook的配置加载、信任审核、超时和退出码语义；
- 真实第三方Hook进程从stdin调用Bridge并在1秒目标/3秒硬超时内退出；
- Bridge未运行、暂存满和进程被杀时，真实源任务的退出结果保持不变（缺失凭据已验证）；
- 管理员策略、跨项目Hook、多个会话并发和工具升级后的行为。

在上述实机证据完成前，`fail_open_hook_exit()` 只是连接器实现必须遵守的可执行契约，不是对第三方工具行为的验证结论。
