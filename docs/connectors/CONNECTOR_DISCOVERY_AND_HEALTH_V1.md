# 圆圆内置连接器发现与认证健康状态 v1

状态：P0 已实现只读发现、显式用户级 Hook 检查与认证失败暂停；真实 Hook 接入仍关闭  
日期：2026-08-04  
实现：`src-tauri/src/connector_discovery.rs`、`src-tauri/crates/yuanyuan-bridge/src/authentication_health.rs`、`src/panel/ConnectorDiscoveryStatus.tsx`

## 1. 状态必须分层

设置页不得用一个“已连接”布尔值混合以下四件事：

1. **安装状态**：本机是否检测到 Codex 或 Claude Code；
2. **授权状态**：圆圆是否拥有该连接器实例的本机认证身份；
3. **Hook 配置状态**：来源工具是否已包含圆圆拥有的 Hook 片段；
4. **事件健康状态**：是否收到过可信事件，或是否因连续认证失败暂停。

检测到可执行文件不等于已授权，已授权不等于 Hook 已配置，Hook 已配置也不等于当前事件链健康。被动发现时 Hook 配置状态固定为 `unknown`；用户可对有效的随机稳定实例另行触发一次脱敏只读检查。兼容性仍固定为 `limited`。

## 2. 只读安装发现

当前 Windows 发现范围只有：

- Codex：Windows 商店/桌面应用注册信息、桌面应用管理目录中的普通 `codex.exe`、PATH 中的独立 `codex.exe/.cmd/.bat`；
- Claude Code：官方原生用户安装位置 `%USERPROFILE%\.local\bin\claude.exe`，以及 PATH 中的普通 `claude.exe/.cmd/.bat`；
- 普通文件必须非空且不是重解析点，避免把符号链接或应用执行别名误报为独立 CLI；
- Codex 桌面应用包内和其本地管理目录中的命令只计为桌面应用，不重复计为独立 CLI。

发现过程不启动来源程序，不执行 `--version`，不读取 `%USERPROFILE%\.codex`、Claude 配置目录、会话、项目、工作区或任务数据，不枚举来源工具私有数据库，也不修改 Hook。返回值不包含检测到的绝对路径。

依据的当前官方安装资料仅用于冻结安装发现边界，不代表事件能力已经冻结：

- OpenAI Windows 桌面应用官方安装说明：<https://learn.chatgpt.com/docs/windows/windows-app.md>
- Claude Code 官方安装说明：<https://code.claude.com/docs/en/installation>
- Claude Code 官方故障排查与 Windows 原生路径：<https://code.claude.com/docs/en/troubleshoot-install>

## 3. 稳定实例身份

被动发现不创建文件、数据库或实例 ID。只有用户显式查看首次授权预览时，稳定核心才在两分钟单次确认操作中生成随机 UUID；确认应用成功后，该 UUID 随信任记录持久化。页面只使用 UUID 关联后续轮换、重置或重连，不把它作为用户可读名称，也不展示密钥编号。

当前内置实现标识为 `builtin.codex` 与 `builtin.claude-code`。Hook 所有权参数已经冻结为 `owner_id + 随机 connector_id + 随机 source_instance`；不得把这两个内置实现标识直接写入真实来源配置。完整格式见 `HOOK_CONFIG_FORMATS_2026-08-04.md`。

新注册身份使用 `<内置实现标识>.<随机 UUID>` 作为稳定 `connector_id`，另配独立随机 `source_instance`；内置实现标识只负责选择适配器。历史上错误使用固定实现标识作为持久身份的记录只读可见，但统一标记为需要重连，不能轮换、重连或写入未来 Hook。系统不静默迁移旧密钥，也不把随机身份显示成用户可读名称。

## 4. 连续认证失败暂停

认证健康库位于 `%LOCALAPPDATA%\Yuanyuan\connector-authentication-health.sqlite3`，只保存连接器身份、连续失败次数、首次/最近失败时间和暂停时间；没有密钥、载荷、路径、错误正文或任务内容。

状态机规则：

- 同一已授权 `connector_id + source_instance` 在十分钟内连续三次可归属的认证失败后进入暂停；
- 只有声明的 `key_id` 在信任库中仍对该精确身份有权限时，失败才计数；未知身份或未知密钥不能填满其他连接器的熔断计数；
- HMAC 通过会清除尚未暂停的失败序列；一旦暂停，普通成功事件不能自行解除；
- 首次授权、轮换、重置或重连成功后，由稳定核心清除该实例的暂停记录；
- 暂停后 Bridge 不再读取密钥或投递该实例事件，记录固定 `authentication_paused` 诊断码；
- 健康库缺失表示尚未观察到暂停；健康库损坏、路径不安全或不可读显示为“状态不可用”，不会伪装成“未配置”。

健康库是防重复故障与用户提示层，不替代 HMAC。健康库不可用时，原有身份绑定、密钥授权、时间窗和 HMAC 校验仍然生效。

## 5. 来源任务不受影响

无效载荷、凭据丢失、连续认证失败和已暂停状态都保持 Bridge 空标准输出、空标准错误和退出码 `0`。这些结果不会写入任务状态机，不会把来源任务改成失败或取消，也不会阻止 Codex/Claude Code 自己完成工作。

真实 CLI 契约测试覆盖：活动信任仍存在但 Credential Manager 凭据缺失时，前三次调用静默记录认证失败，第三次持久化暂停，第四次直接返回暂停诊断；四次进程退出均成功且在 Hook 目标时限内完成。

## 6. 当前设置页

设置页“任务守望连接器”卡片只显示：

- 是否检测到安装及安装渠道；
- 授权是否有效、未配置、需重连或不可读取；
- Hook 被动发现时尚未检查；有效随机实例可由用户点击后只读检查用户级配置，并仅显示脱敏计数/冲突状态；
- 事件尚未观察、认证失败已暂停或健康状态不可读取；
- 本轮检查没有启动来源工具、读取私人数据或修改 Hook。

卡片提供“重新检查”、有效实例上的“只读检查 Hook 配置”和可展开的“未来授权范围”说明。自动发现不读取配置；显式 Hook 检查只读取对应工具的用户级配置，不读取项目、会话或任务正文，不启动来源工具，也不写入文件。授权说明只展示将创建本机专用凭据/随机身份，以及不会暴露密钥、读取任务正文、改变来源任务或修改 Hook；它不会签发确认令牌，也没有 Hook 写入执行按钮。Bridge 与 AI 仍被正式安装包排除，因此该卡片不能解释为 v2.0A 已可用。
