# ADR-0008：返回原工具的注册动作与目标校验

状态：Accepted for P0<br>
日期：2026-08-04<br>
对应实现：`src-tauri/crates/yuanyuan-protocol/src/lib.rs`（语法边界）、`src-tauri/src/return_action_registry.rs`（稳定核心门禁）<br>
对应方案：最终设计11.8/16.5、开发方案P0-013/P1-E03

## 背景

任务事件可能提示用户“回到Codex/Claude继续处理”。如果把Hook提供的URI、文件路径或命令直接交给Shell，恶意或被污染的事件可以执行程序、打开敏感文件、注入命令行参数或把凭据传给非预期目标。HMAC只证明事件来自已配置连接器，不代表载荷中的返回目标天然安全。

## 决策

- 协议只携带`action_id + target`；`action_id`是最多128字节的小写ASCII注册标识，不能是URI、路径或命令；`target`是不透明字符串，最多2048字节；
- Bridge只验证协议与认证并原样传递，绝不解释或执行返回动作；AI只存储和转发结构化意图，也不调用Shell；
- 稳定核心维护随版本发布的注册表。由于正式`connector_id`包含每次授权生成的随机实例后缀，编译期注册键使用“内置连接器实现族 + 精确`action_id`”，校验时再同时绑定完整`connector_id`、独立`source_instance`和协议`source`；不接受通配来源、历史固定身份或普通配置扩展。未注册组合、连接器不匹配、空目标或目标解析失败一律拒绝；
- 注册项必须声明目标类型、规范化规则、最大长度、处理器和安全降级。v2.0A只允许打开已知任务或回到圆圆任务台，不提供通用“打开URI/文件/命令”动作；
- 渲染按钮前校验一次，用户点击后使用最新注册表再校验一次，避免存储后升级、配置变化或前端绕过；
- 处理器不得调用Shell字符串拼接。需要调用外部工具时使用固定可执行身份和结构化参数；目标只可来自已验证的连接器任务标识，不能附带任意参数；
- 默认拒绝`file://`、`shell:`、`cmd:`、PowerShell、脚本解释器、UNC路径、相对/绝对文件路径、控制字符、NUL和未注册自定义协议；
- 若目标无法安全返回，稳定降级为打开圆圆任务台并展示脱敏来源、任务标识和“原工具入口不可用”，不尝试猜测路径；
- 动作执行是明确用户点击，不由模型、Hook或任务终态自动触发；锁屏状态不得绕过Windows认证。

## 注册表最小契约

每个注册项必须声明：

| 字段 | 含义 |
| --- | --- |
| `connector_id` | 完整随机实例身份；必须解析为已编译内置实现，不接受历史固定身份或第三方命名空间 |
| `action_id` | 精确动作标识 |
| `target_kind` | 如`task_id`或受限`thread_id`，不提供`uri`/`command`通用类型 |
| `validate_target` | 长度、字符集、前缀和规范化后相等性检查 |
| `handler` | 编译期绑定的稳定核心处理器 |
| `fallback_route` | 固定为圆圆任务台内的安全页面 |
| `audit_code` | 不含原始敏感目标的稳定结果码 |

注册表不能由Hook、模型输出、远程Provider或普通配置文件动态扩展。新增动作属于安全边界变更，必须链接本ADR和威胁模型T11的测试证据。

## 验证要求

- 协议拒绝URI样式和非法`action_id`；
- 每个正式连接器提供合法目标、空目标、超长目标、控制字符、路径穿越、URI、命令片段和连接器错配夹具；
- 渲染前与点击后校验结果一致；升级后已存储但已撤销的动作关闭失败；
- 处理器测试证明不经过Shell，失败只打开任务台或不执行；
- 未经点击、模型输出或任务事件本身不能执行动作；
- 日志只记录连接器、动作标识、脱敏目标摘要和结果码。

## 当前实现与边界

稳定核心已实现首版静态注册表和双重校验门禁：仅识别两个内置连接器族的精确`open.task`动作；目标必须是1—128字节、只含ASCII字母、数字、`-`或`_`的不透明任务标识。文件、URI、命令、脚本、路径分隔符、控制字符、首尾空白和非ASCII全部关闭失败。

渲染阶段校验成功后只生成最长2分钟、最多64个待处理的一次性UUID能力凭证；前端凭证不含原始目标。点击后先消费凭证，再以当前注册表复核连接器、来源、动作、规范目标及域分隔摘要；过期、重放、注册撤销或目标篡改均不能执行外部动作。审计关联值只保留16位十六进制摘要，不保留原始目标。

Codex和Claude Code的正式返回处理器尚未通过版本、签名、窗口及无障碍验收，当前注册处理器固定为`SourceTaskUnavailable`。因此即使两次校验都通过，也只产生“打开圆圆任务守望台”的内部降级决策；该门禁尚无Tauri命令或正式按钮，任务事件、模型输出和前端都不能自行触发。只有正式来源处理器过门后才会单独开放命令面。

## 未选择方案

- 直接打开连接器给出的URI：签名来源也可能被污染，且无法约束协议与参数；
- 仅由前端校验：可被后端调用、存储旧数据或前端缺陷绕过；
- 维护允许协议前缀列表：自定义协议处理器本身可能执行命令，前缀不足以证明参数安全；
- 让模型生成返回目标：模型输出是不可信建议，不能成为权限或目标的唯一证据。
