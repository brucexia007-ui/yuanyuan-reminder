# ADR-0001：稳定核心、智能进程与任务桥故障域

状态：Accepted for P0<br>
日期：2026-08-03<br>
对应方案：最终设计8.3、开发方案P0-E02

## 背景

现有 `YuanyuanReminder.exe` 同时承载提醒调度、SQLite、Windows集成、托盘、宠物窗口和任务面板。v2计划增加外部Hook、模型Provider、记忆检索和工具编排。若这些高变化、高负载或需要网络的能力继续与提醒核心同进程，模型崩溃、数据库迁移、连接器风暴或网络阻塞都可能破坏圆圆已经可靠的离线提醒能力。

## 决策

采用三个可独立停止、升级和熔断的进程：

1. `YuanyuanReminder.exe`：稳定核心。保留提醒、宠物日常、确定性表达导演、窗口和用户确认；不直接访问模型Provider；
2. `YuanyuanAI.exe`：智能与守望进程。承载任务状态持久化、Provider、记忆、工具编排和独立 `yuanyuan-ai.sqlite3`；
3. `YuanyuanBridge.exe`：最小任务桥。只做输入限制、协议转换后的认证、快速入队和fail-open；不访问网络、不调用模型、不执行数据库迁移。

数据边界：

- `yuanyuan-reminder.sqlite3` 只保存现有提醒、喝水、专注、互动、历史和设置；
- `yuanyuan-ai.sqlite3` 从v2.0A开始保存连接器、任务和事件，v2.0B再增加会话、信息文档和记忆；
- 两个数据库不共享连接、事务或迁移；AI库不可用时只关闭智能能力；
- 凭据正文进入Windows Credential Manager，不进入任一数据库、日志或备份。

运行边界：

- 主程序监督AI进程健康状态，但连续崩溃后熔断，不无限重启；
- Bridge或AI进程未运行、超时、队列满或载荷无效时，外部Hook继续执行；
- AI进程停止后，v1.4.0全部能力继续可用；
- 只有AI进程允许访问模型网络，WebView保持IPC-only；
- 协议不兼容时先停用高层能力，不让不兼容进程访问稳定核心。

## 未选择方案

- 单进程内用线程隔离：不能隔离进程崩溃、地址空间耗尽和依赖升级；
- 完整引入OpenClaw或Hermes运行时：增加供应链、体积和权限面，不符合轻量离线底座；
- 让Bridge写提醒数据库：会把外部事件失败和锁竞争引入核心数据；
- Hook直接请求主程序HTTP或云模型：扩大攻击面并可能阻塞源任务。

## 影响

正面影响：提醒可靠性和智能能力解耦；可独立升级、诊断和关闭；网络与数据边界清楚。

代价：需要多进程打包、协议协商、进程监督、签名、杀毒误报和升级顺序测试。

## P0/P1验证条件

- AI进程连续崩溃时提醒调度和宠物窗口继续运行；
- Bridge正常与所有异常路径目标1秒、硬超时3秒并fail-open；
- AI数据库损坏或迁移失败不访问、不锁定提醒数据库；
- 三个exe能够使用统一发布身份签名并被安装器正确升级/回退；
- 24小时任务守望和72小时发布候选无持续内存增长、队列堆积或提醒风暴。

未达到这些条件时，本ADR状态不得升级为Accepted，对应阶段不得发布。
