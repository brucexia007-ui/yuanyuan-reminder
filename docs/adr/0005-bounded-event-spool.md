# ADR-0005：受限事件暂存、损坏隔离与安全重放

状态：Accepted for P0<br>
日期：2026-08-04<br>
对应实现：`src-tauri/crates/yuanyuan-bridge/src/spool.rs`<br>
对应方案：最终设计20.4、开发方案P0-025/P1-E03

## 背景

智能进程或命名管道短暂不可用时，Bridge需要在不阻塞源Hook的前提下保留少量已认证事件。普通JSON文件队列无法证明完整性，也容易因部分写入、重复事件、损坏文件或无限增长导致启动循环、磁盘耗尽和重复提醒。

## 决策

暂存只接收已经通过协议、时间窗和HMAC验证的原始认证事件，但预验证阶段不登记nonce；最终接收者成功验证并原子登记nonce后才确认并删除暂存文件。这样既阻止无效输入灌盘，也避免预暂存提前消费nonce导致合法重放被拒绝。

每个事件使用版本化二进制帧：

- 8字节魔数`YYSPV001`；
- 大端u16 schema版本，当前为1；
- 大端u32载荷长度；
- 大端u32 CRC32C；
- 大端i64落盘时间；
- 最多64KiB的原始认证事件。

写入先在`pending`目录以`create_new`创建专属临时文件，完整写入并`sync_all`后在同一目录原子改名。SHA-256内容摘要用于重试去重，文件名前缀保存固定宽度时间以维持重放顺序。跨线程和跨进程操作使用操作系统文件锁串行化容量检查、去重、改名、重放和隔离。

默认容量：pending最多256个文件或8MiB；quarantine最多64个文件或4MiB；单批最多重放64个事件。容量已满时Bridge丢弃本次暂存并继续fail-open，不覆盖尚未确认的正常事件。隔离区达到上限时按时间顺序删除最旧损坏项，为新损坏证据留出空间。

schema、长度、时间、文件类型或CRC32C异常的帧不进入认证、nonce表、任务状态机或UI，直接移动到`quarantine`。消费者可返回确认删除、稍后重试或主动隔离；稍后重试会停止本批，避免越过旧事件造成顺序反转。进程崩溃遗留的本模块临时文件只在取得同一跨进程锁后清理，不删除其他临时文件。

## 当前证据

自动化测试覆盖CRC32C标准向量、原子提交、内容去重、确认后删除、RetryLater顺序、schema/长度/CRC损坏隔离、文件数与字节硬上限、隔离区轮换、崩溃临时文件清理、并发重复写入、锁竞争不落盘，以及“签名通过但不消费nonce→暂存→最终验证并确认”的完整路径。篡改事件不会触达传输或磁盘。最终CLI已把默认目录固定到当前用户的`%LOCALAPPDATA%\Yuanyuan\bridge-spool`，并在创建任何队列文件前应用当前用户专用DACL；传输成功路径不会创建该目录。

## 剩余门禁

- 把已实现的ACK传输能力接入独立AI进程的真实提交事务，确保“验证、nonce登记、持久化成功后才ACK”；
- 使用真实受控Credential Manager凭据覆盖最终CLI成功发送与失败暂存路径；
- 进程被强制终止、磁盘写满、只读目录、杀毒软件占用和睡眠恢复故障注入；
- 24/72小时队列增长、重放吞吐和隔离区清理观测；
- 明确卸载、重置信任和彻底删除时的暂存清理策略。

上述门禁通过前，暂存不可加入正式安装包或真实Hook配置。
