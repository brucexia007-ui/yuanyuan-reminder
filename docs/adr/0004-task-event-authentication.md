# ADR-0004：任务事件HMAC认证与重放防护

状态：Accepted for P0<br>
日期：2026-08-03<br>
对应协议：`docs/protocol/TASK_EVENT_AUTH_V1.md`<br>
对应实现：`src-tauri/crates/yuanyuan-bridge/src/authentication.rs`

## 决策

每个连接器实例使用独立`key_id`和至少32字节的HMAC-SHA-256密钥。事件签名覆盖认证版本、密钥标识、16字节随机nonce、Unix毫秒时间戳和任务事件全部已知语义字段。签名消息采用长度前缀二进制编码，不依赖JSON属性顺序、空白或转义形式。

验证窗口为本机时间前后各5分钟。只有HMAC校验成功后才原子登记nonce；重复nonce拒绝。未知、吊销或不可读取的密钥拒绝；nonce存储不可用时也拒绝，不采用“先接受以后补记”的降级方式。

密钥正文必须进入Windows Credential Manager并按`connector_id + source_instance`隔离，不进入数据库、日志、诊断、备份或UI。生产凭据使用本机后续登录会话可见的持久化级别。轮换先创建新凭据再提交信任切换；旧密钥只接受切换前签署且在最长五分钟宽限内收到的事件。吊销先移除信任权限再删除凭据，不保留宽限，也不因删除失败恢复权限。完整状态机见`docs/protocol/CONNECTOR_TRUST_LIFECYCLE_V1.md`。

所有认证错误对源Hook保持fail-open退出码0。产品内部只记录稳定的脱敏分类和计数，不记录nonce、MAC、密钥正文或完整载荷。

## 未选择方案

- 仅依赖命名管道DACL：不能防止同一用户会话内其他进程伪造事件；
- 对原始JSON文本签名：跨语言序列化的字段顺序、浮点和转义差异会造成不稳定；
- 只签`payload_digest`：无法覆盖任务身份、状态、证据等级和返回动作等关键字段；
- HMAC失败后仍暂存：会扩大无效输入的磁盘攻击面；
- nonce只存内存：进程重启后无法阻止有效时间窗内的重放。

## 当前证据与剩余门禁

当前代码已覆盖正确签名、篡改、时钟窗口、重放、身份绑定、旧事件轮换窗、立即吊销、永久`key_id`墓碑、事务回滚、容量边界、脱敏状态和固定跨连接器向量。稳定核心是信任库唯一写入者；Bridge与AI只读信任库并在授权后读取Credential Manager。真实Windows夹具验证生成密钥、两阶段轮换、宽限清理、立即重置和生产级本机持久化；真实Bridge CLI完成身份校验、签名、管道ACK并保持静默。SQLite nonce与事件、任务状态继续原子提交。

尚未完成的生产门禁：真实连接器实例发现和Hook差异/备份/信任审核、连续认证失败停用、跨Windows账户拒绝、系统睡眠后的时钟策略，以及安装升级/回退测试。当前确认接口不修改Hook配置；上述门禁通过前不得配置真实Hook。
