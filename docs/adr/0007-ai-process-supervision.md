# ADR-0007：AI进程健康、退避与熔断监督

状态：Accepted for P0<br>
日期：2026-08-04<br>
对应实现：`src-tauri/src/ai_supervisor.rs`、`src-tauri/crates/yuanyuan-ai/src/lib.rs`<br>
对应方案：最终设计8.3、开发方案P1-E01/P2-Core C-E01

## 背景

AI进程是高变化故障域。稳定核心需要在AI可用时启动和监督它，但不能因程序缺失、版本不兼容、启动超时或连续崩溃而阻塞提醒调度、宠物窗口或正常退出。

## 决策

- 稳定核心只解析自身可执行文件同目录下的固定文件名`yuanyuan-ai.exe`，不从`PATH`、注册表或事件载荷寻找程序；
- AI程序缺失时状态为`Unavailable`，提醒核心继续运行；
- AI控制管道v1接受固定健康消息，只有收到协议ACK才进入`Running`；启动健康门为3秒；核心与AI支持的版本区间必须有交集，过旧、过新和无效区间均关闭失败；
- 异常失败采用1秒、2秒指数退避；5分钟滑动窗口内第三次失败打开熔断，不再自动重启；
- 熔断后仅接受用户或本地诊断界面触发的显式重试；重试创建新的监督周期，不允许在`Starting`、`Running`或普通退避阶段并发启动第二个AI实例；
- 连续健康运行满5分钟后清除历史失败；
- 主程序完全退出时先发送版本化关闭请求并等待最多2秒，只在自己启动的子进程未退出时执行终止；
- 子进程stdin/stdout/stderr均关闭并使用无窗口模式，不能向提醒核心或Hook注入控制输出；
- 当前P0构建仍不把AI程序加入NSIS，监督器在正式发布门通过前保持安全不可用状态。

## 当前证据

单元测试覆盖程序路径固定、程序缺失无工作线程、退避序列、失败窗口过期、健康运行重置、第三次失败熔断、显式恢复和逻辑兼容矩阵。真实Windows子进程夹具覆盖三个进程立即崩溃后熔断、显式恢复后重新进入监督并再次熔断，以及长驻但不提供健康协议的进程被超时终止；崩溃循环中提醒设置、今日事项和专注事务持续成功。AI服务真实管道测试覆盖v1健康请求、未知v2请求关闭失败、连续事件与优雅关闭；独立`yuanyuan-ai.exe`调试子进程矩阵覆盖v1/v2双向拒绝、正确版本恢复和版本化关闭。设置页组件测试覆盖未安装时隐藏，以及熔断时说明降级并提供一次显式恢复。完整工作区和不含AI sidecar的NSIS构建均通过。

## 剩余门禁

- 面向用户的熔断说明、诊断清除和显式恢复界面；
- AI数据库损坏、迁移失败和高频崩溃期间的完整提醒调度与宠物窗口E2E；
- 本地诊断卡片在真实Tauri窗口、不同DPI和键盘操作下的视觉验收；
- 使用历史签名发布二进制验证版本不兼容、升级中断、旧AI/新核心及新AI/旧核心矩阵；
- 签名身份校验、安装器集成、升级和回退。

这些门禁通过前，不把AI或Bridge加入正式安装包。
