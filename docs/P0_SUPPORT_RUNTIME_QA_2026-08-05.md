## 1. 运行环境与方法

- 直接启动本轮 release 主程序，不使用浏览器演示数据；
- 通过第二实例触发正式单实例回调，显示真实 `panel` 窗口；
- Tauri 配置逻辑尺寸为 390×620，DPI 感知的完整窗口抓取为 607×943 像素（包含透明窗框范围）；
- 只向已核实属于“圆圆提醒”的 `Chrome_RenderWidgetHostHWND` 子窗口发送固定坐标点击；没有读取或控制其他应用窗口；
- 宠物和面板图像均由对应窗口的 `PrintWindow` 结果生成，没有截取整个桌面；
- 测试结束前手动结束 5 分钟会话，并按精确程序路径关闭 PID 50540 测试实例。

## 3. 运行时边界观察

- 当前陪伴中的宠物窗口只出现猫咪本体动作，没有系统信息卡、提词器、气泡或自由文本；
- 活动会话结束后选择器可以重新打开，没有连续天数、奖励、追问或延长邀请；
- 会话开始和结束没有导致主进程退出；等待期间面板曾被隐藏，但进程和日志保持正常，重新显示后状态正确；
- 测试期间喝水统计从 0 变为 1，但没有证据能将其归因于本轮窗口自动化或用户操作，因此没有修改、删除或回滚该记录。

## 4. 未通过与不能宣称的项目

- Windows UI Automation 当前只枚举到 Tauri/WebView 容器，没有取得内部按钮的可访问子树，不能据此声明 Narrator 已通过；
- `SendKeys` 键盘注入被当前 Windows 会话以 `Access is denied` 拒绝，不能据此声明完整 Tab 顺序已通过；
- 临时 WebView2 调试端口没有开放，该失败路径没有作为交互证据；
- 本轮只有当前显示环境的一次 DPI 感知抓取，不代表 100%/125%/150%/200% 全矩阵；
- 尚未验证 Windows 高对比度、系统减少动态、150%/200% 文本缩放和真实屏幕阅读器；
- 尚未进行目标用户 60 秒介绍后的三状态辨识率测试。

本轮实拍后，正式界面已补上确定性焦点恢复和清晰 `:focus-visible` 焦点环，并用前端回归覆盖“打开→第一张小牌、取消→入口、开始→结束按钮、手动结束→入口”。这是代码级改进，不改变上述真实键盘与屏幕阅读器发布门结论。

随后生产样式又补上Windows强制颜色适配，覆盖面板、三路径选择、选中/禁用态、宠物系统卡、操作按钮及焦点环，并由静态回归阻止规则缺失。这仍是代码证据；本轮没有切换真实Windows高对比度主题重新实拍，因此高对比度发布门仍未通过。

因此，S-E01 的正式代码和本轮真实窗口视觉路径可以继续保留在构建中，但 P0-E05/P0-E07 的无障碍、多 DPI 和用户辨识发布门仍保持打开。
