# “理一理”数据去向与单次授权协议 v1

状态：P0 体验与安全边界冻结；开发实验台、Rust 内存单次授权核心、授权后固定请求/结果层及独立IPC Schema原型已实现，尚未接入生产传输、命令或真实 Provider，正式 Support Box 继续关闭。

## 1. 目标

“理一理”会把用户主动输入的一段内容整理为“事实、感受、可控、下一步”。在出现输入框、调用 Provider 或创建任何请求之前，界面必须先让用户看懂内容去向，并取得一次性的明确授权。

该流程不等同于圆圆说话。圆圆只在整理板旁做固定动作；数据去向、授权和结果属于独立工具界面。

## 2. 固定顺序

正式实现必须遵循：

`选择去向 → 查看数据流 → 明确确认 → 单次授权 → 才允许输入/提交 → 授权立即失效`

不得先收集正文再补授权，不得把“打开理一理”“选中去向”或“勾选记住选择”解释为发送授权。

## 3. 两种去向

### 3.1 仅在本机整理

- 只交给经过本机信任检查的本地 Provider；
- 圆圆不把正文写入提醒库、AI任务库、日志、诊断、分析或备份；
- 本地 Provider 自身的模型文件和运行缓存必须在后续 Provider 质量门中单独披露；
- 本机 Provider 不可用时关闭失败，不静默改用云端。

### 3.2 交给云服务整理

- 授权前必须显示具体 Provider 身份和其数据保留说明入口；
- 只允许发送用户在本次工具中主动输入的正文，不得附带任务正文、文件、历史倾诉、记忆、工作区或剪贴板；
- 云 Provider 未配置、身份变化或披露版本变化时必须重新授权；
- 云端不可用时不得静默改成本机，也不得反向降级后继续发送。

## 4. 单次授权绑定

授权只绑定以下固定字段：

- 用途：`structure_fact_feeling_control_next_step`；
- 内容类别：`user_entered_text`；
- 去向：`local_provider` 或 `cloud_provider`；
- Provider 的不透明身份与版本指纹；
- 数据去向披露版本；
- 最长五分钟有效期；
- 最多使用一次。

授权记录和提交凭证不得包含用户正文、整理结果、情绪推断、任务身份或工作区路径。`yuanyuan-ai` 已实现 Rust 内存单次能力核心：使用随机不透明令牌、五分钟固定有效期、64项容量上限，并在消费时重新核对去向、Provider身份/指纹和披露版本。开发实验台中的前端回执仍只验证交互顺序；生产接线必须由 Rust 能力核心签发和消费，不能信任前端回执。

授权后的 Provider 请求由 AI 进程内的固定入口构造：Provider 身份来自字段私有且已校验的 Rust 描述对象，并与一次性适配器注册成对使用，不能由前端在提交时临时拼装。入口先在本机校验用户主动输入的正文，再消费与当前描述完全一致的授权，随后只构造以下固定输入：

- `schema_version=1`；
- `content_class=user_entered_text`；
- `user_entered_text`，保持用户本次输入的原文；
- 固定操作 `SupportSort` 和30秒超时属于宿主控制，不作为正文上下文发送。

授权令牌、Provider身份/指纹、任务、历史、记忆、文件、工作区和剪贴板均没有进入该请求的参数。正文为空、超过16 KiB、包含 NUL 或 Unicode 双向格式控制符时在消费授权前本机拒绝；授权一旦消费，即使适配器能力检查或启动失败也不得复用。

Provider输出还必须经过“理一理”专用结果门，不能把通用模型回复直接交给圆圆或界面。该门只接受：

- 精确的 `present_information + normal` 非语言呈现意图；
- 标题“理一理”、来源“整理结果（请核对）”、`model_inferred + unknown + sensitive` 固定元数据；
- 唯一一张四列表格，列名依次为“事实、感受、可控、下一步”，且只有一行；
- 零引用、零模型生成动作。

结构通过后还必须经过确定性语义预审门：明确的猫咪对白、诊断、他人动机臆测、强迫指令、依赖/内疚诱导、虚假保证、效率施压、结构问题最小化、危机/医疗处置以及URL/脚本/命令全部关闭失败。强迫词只在“可控/下一步”判为指令，“事实”可以保留用户或负责人原话。各格和总文本另有更严格字节上限，并拒绝换行、制表符与双向控制符。通过后，AI进程会丢弃通用响应意图和显示文档外壳，只向未来工具界面返回四个字符串与可选用量；不向猫咪表达层暴露模型对白。解析后的文档在任何拒绝路径都会主动清理全部文本所有者。完整边界见`../P0_SUPPORT_SORT_SEMANTIC_PRE_REVIEW_2026-08-08.md`。

固定词门只能拦截明确红线，不能理解所有隐喻、方言、上下文或规避表达，也不是危机分类器；真实Provider语义金标准、专业复核和独立静态地区安全面板仍是开放前硬门。

跨进程接线使用独立的 `SUPPORT_SORT_IPC_PROTOCOL_V1.md`，不扩写健康/关闭控制协议，也不复用任务事件管道。严格请求/响应Schema、AI进程内可信分发器、随机私密会话引导、有界双向命名管道和客户端PID/创建时间验证已经实现：先查询注册表生成的Provider披露摘要，再确认签发，提交只带授权绑定和本次原文，适配器只在授权消费后创建，响应只带四格；正式Tauri命令、真实签名/包身份正向证据、第二账户和真实Provider仍未完成。

## 5. 必须重新授权的情况

- 用户切换本机/云端；
- Provider 身份、版本指纹或披露版本变化；
- 授权超过五分钟；
- 授权已使用一次；
- 用户取消、关闭窗口或重新开始；
- 应用或 AI 进程重启；
- 发送前发现当前 Provider 与授权绑定不一致。

不得提供跨会话的“永远允许”。未来可以记住默认去向，但进入“理一理”后仍要展示去向并取得本次授权。

## 6. 取消与故障

- 在提交前取消必须产生零 Provider 请求；
- Provider、网络、凭据或授权校验失败时不消费另一个去向的权限；
- 失败后正文仍不得进入日志、诊断、分析或任务数据库；
- 界面只说明工具状态，不让圆圆用第一人称对白解释失败；
- 未通过专业复核、地区资源和 Core Provider 质量门时，正式构建不得显示“理一理”入口。

## 7. P0 自动验收

至少冻结以下行为：

1. 未查看数据流不能授权；
2. 未授权不能产生提交回执；
3. 切换去向、Provider 变化、过期和使用一次后都要求重新授权；
4. 取消后状态中不存在去向、授权或正文，提交次数保持零；
5. 回执只含固定枚举、Provider 不透明身份/指纹、披露版本和有效期；
6. 源码不依赖网络、Tauri 调用、浏览器存储、日志或分析接口；
7. 生产构建不包含实验台入口、文案或样式。
8. Rust固定请求层只能把本次用户原文交给适配器；令牌、Provider绑定及其他上下文不得出现在请求中。
9. Rust专用结果门只返回事实/感受/可控/下一步四字段，不暴露通用模型回复或模型动作。
10. 结构合法但含明确语义红线的四格必须关闭失败；被拒绝的解析文档全部文本所有者必须主动清理。

真实本机/云 Provider、前端到 Rust 的授权命令接线、真实崩溃/换页取证和专业/地区复核属于后续硬门，不由开发适配器、固定词门或纯Rust回归替代。
