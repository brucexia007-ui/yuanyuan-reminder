# 任务守望主动提示暂缓协议 v1

更新时间：2026-08-06  
状态：稳定核心与正式任务守望界面已实现

## 用户语义

用户只能从任务守望台对一组“来源 + 固定状态”执行“10 分钟后再提醒”或“恢复提醒”。暂缓只停止圆圆针对该组状态的主动动作、道具前推和提示，不隐藏任务状态、不暂停或修改来源任务，也不尝试打开、关闭或重试 Codex / Claude Code。

可暂缓状态固定为 `running`、`waiting_user`、`failed`、`stalled`、`unknown`。`queued`、`succeeded`、`cancelled`没有暂缓入口。正式命令只接受 10、30、60 分钟，当前界面仅提供 10 分钟。

## 数据边界

主提醒库 schema v11 的 `task_watch_attention_deferrals` 只保存：

- `source`：`codex`或`claude_code`；
- `state`：上述五种固定状态之一；
- `deferred_until_unix_ms`；
- `updated_at_unix_ms`。

主键为“来源 + 状态”。表内没有任务标识、摘要、标题、正文、提示词、消息、会话、工作区或路径。任务守望快照 schema v2 只在已有聚合状态上附加可空的暂缓截止时间；前端不显示精确时间。

## 生命周期与仲裁

1. 用户显式点击后，稳定核心校验来源、状态、固定时长与时钟，再以事务写入或续期；
2. 任务继续出现在守望台，只从圆圆的候选表达中移除匹配的“来源 + 状态”；其他来源和其他状态不受影响；
3. 到期的运行、等待、疑似停住或未知状态恢复正常表达；
4. 到期的失败状态即使已超过普通30秒终态窗口，也会生成一次不含任务身份的聚合失败表达；同一时刻多个来源到期时逐来源呈现，不把一个来源的数量归到另一个来源；
5. 专注、一键安静、基础陪伴、本地提醒或其他更高优先级状态会继续阻止失败摘要；未真正呈现的到期失败记录不会被消费；
6. 到期记录仅在表达导演本轮更新成功后按“来源 + 状态 + 原截止时间”确认删除，用户在并发续期时不会被旧确认误删；
7. 用户点击“恢复提醒”会立即清除该组暂缓并重新计算表达。

## 失败与兼容

- 数据库、任务状态库或表达更新失败时返回固定失败语义，来源任务不受影响；
- 非 Windows、浏览器生产环境、未知来源、未知状态和未知时长全部关闭失败；
- 浏览器固定状态演示只在开发模式且显式带 `taskWatchDemo=1` 时生效，不进入正式安装包；
- 本协议不提供返回来源工具、外部协议处理器、Shell、文件或路径能力；返回动作仍受独立安全门禁控制。

## 验证要求

- v10→v11迁移与既有数据保留；
- 持久化、续期、清除、到期一次性消费、并发续期保护和非法输入；
- 暂缓不隐藏守望台状态、只抑制匹配表达、其他来源不受影响；
- 非终态到期恢复、失败到期逐来源聚合、专注等抑制时不丢失；
- 390×620布局、键盘焦点、固定无障碍名称和无任务身份字段。
