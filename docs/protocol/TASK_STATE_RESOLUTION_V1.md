# 任务状态归组与证据解析 v1

状态：P1-E02实现契约  
日期：2026-08-06  
实现：`yuanyuan-protocol`、`yuanyuan-ai`

## 1. 目标

本契约规定认证后的任务事件如何归组、落盘和进入圆圆的非语言表达。它不改变来源任务，不把来源声称的状态直接当作用户可见事实。

## 2. 任务与运行边界

- 任务键覆盖`connector_id + source_instance + source + workspace + external_id + task_id`；相同外部标识在不同工作区或不同来源实例中必须形成不同任务。
- `sequence`在同一任务生命周期内单调递增，包括跨`run_id`；低序号事件只作为审计证据保存，不回退当前摘要，相同序号绑定不同事件时拒绝转换。
- 活动运行不能被另一个`run_id`静默替换。只有当前运行已经进入来源终态后，未曾成为当前状态的新运行才可开始。
- 曾以`applied`状态成为当前运行的旧`run_id`不能再次成为当前运行；迟到事件保存为`ignored_stale`。
- 提前到达并被拒绝的新运行不视为历史运行；当前运行正常结束后，该运行仍可用更高序号合法开始。

## 3. 父子任务

- 任务不能把自身`task_id`声明为`parent_task_id`。
- 子任务可以先于父任务到达；父任务不存在不阻止子任务落盘，也不创建伪造父记录。
- 同一运行中允许从“父任务未知”补全为一个固定父任务。
- 后续事件省略父任务时，当前摘要继续保留已经确认的父关系。
- 同一运行中把已有父任务改为另一任务会保存为`rejected_transition`，但不改变当前摘要；新运行可以重新声明父关系。

## 4. 证据等级与用户可见状态

来源事件保留原始`state`、`finality`、`evidence_type`和`evidence_level`作为审计证据。`watched_tasks.evidence_level`只保存当前摘要的固定证据等级；前端不读取完整事件正文。

以下状态属于决定性表达：

- `waiting_user`
- `succeeded`
- `failed`
- `cancelled`

只有`authoritative`证据可把这些状态交给任务守望台和表达导演。`partial`、`presence_only`或`unknown`证据统一投影为`unknown`，因此不会触发确定成功、失败、取消或需要用户的铃铛表达。

非权威来源终态不锁死任务：后续继续运行事件、更强证据或权威结果可以更新摘要。只有权威终态在同一运行内变更为另一终态时要求`finality=corrected`。相同非权威终态在没有更强证据时只保存为重复终态，不重复呈现。

从schema v3升级的既有任务统一得到`evidence_level=unknown`，直到新的已认证事件刷新；迁移不能从旧JSON猜测可信度。

## 5. 原子性与审计

- nonce、事件和当前摘要在一个`BEGIN IMMEDIATE`事务中提交；任一写入失败全部回滚且不发送ACK。
- 乱序、旧运行、重复终态和非法转换仍进入`task_events`并保存固定`disposition`，但不改变当前摘要。
- 完全相同的签名事件重试返回`AlreadyCommitted`；相同事件标识绑定不同认证身份或nonce时拒绝。
- 只读表达链最多读取64项`task_key/source/state/evidence_level/updated_at`固定字段；标题、正文、工作区、任务标识和完整事件JSON不跨入稳定核心。

## 6. 自动化证据

当前测试覆盖：乱序、序号碰撞、幂等重试、活动运行替换、旧运行回流、提前拒绝后合法新运行、父子乱序到达、父关系补全/省略/改挂、跨工作区隔离、权威终态纠正、非权威终态继续运行、schema v3→v4及失败回滚，以及Codex部分完成事件经过连接器、签名、数据库和只读表达链后只能成为`unknown`。
