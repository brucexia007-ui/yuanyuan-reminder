# 任务事件保留与有界清理 v1

状态：P0 数据层、调度与新库增量回收策略；已接入启动后延迟清理及6小时低频重复，长期真实负载校准仍待完成。

## 默认窗口

| 数据 | 默认保留 | 说明 |
| --- | ---: | --- |
| 普通进度事件 | 7天 | `queued/running/unknown` 等可由最新状态重建的中间事件 |
| 优先事件 | 90天 | `waiting_user/succeeded/failed/cancelled` 或 `terminal/corrected` 证据 |
| 终态任务摘要 | 180天 | 任务当前状态为成功、失败或取消 |
| 长期无更新的非终态任务摘要 | 365天 | 不虚构终态，但避免永久保存已失联的任务 |
| 过期认证nonce | 到期即清理 | 仅删除已过认证窗口的去重材料 |

优先事件窗口长于普通进度，因为用户需要理解“为什么找我”“最后发生了什么”和终态纠正。任何仍存在的任务摘要，其 `latest_event_id` 对应事件不受事件窗口清理；任务摘要到期时才由外键级联删除。

## 原子性和批次

- 每轮最多直接选择1,000条旧事件和250个旧任务；
- 选择顺序固定为时间、再按稳定标识，重复运行可继续收敛；
- 事件、任务和过期nonce在一个 `BEGIN IMMEDIATE` 事务中清理；
- 任一触发器、锁、磁盘或SQL错误会回滚全部副作用；
- 输出只返回三类删除计数，不返回标题、路径或事件正文；
- 策略必须满足 `进度 ≤ 优先 ≤ 终态任务 ≤ 失联任务 ≤ 3650天`，批次上限也有硬范围；非法策略在写入前拒绝。

## 不做的事

- 不把超时的运行任务自动改写成失败、成功或取消；
- 不因为清理而生成宠物提醒；
- 不在 Bridge Hook 关键路径执行数据库清理；
- 不清理提醒数据库、记忆、支持偏好或用户手动备份；
- 不运行阻塞式全库 `VACUUM`；只有创建前已冻结为`auto_vacuum=INCREMENTAL`的新库，才在逻辑清理提交后逐页回收且每周期最多256页；
- 既有`auto_vacuum=none`库和含未知v0用户表的数据库不被隐式重写或转换；
- 不把保留策略当作备份、审计合规或用户主动删除的替代品。

## 当前验证

自动化覆盖普通/优先窗口差异、最新事件豁免、终态与长期失联摘要、批次重复收敛、过期nonce，以及故障时事件/任务/nonce整体回滚。

常驻 AI 服务只有在任务管道和控制管道均已就绪后，才启动独立后台线程；后台线程先等待5秒，使用独立数据库连接执行默认策略清理，此后每6小时低频重复。逻辑删除事务成功后，新库才执行最多256页的有界增量回收；增量回收失败不撤销已经提交的保留结果，也不影响健康状态或下一轮。服务优雅退出会立即唤醒并回收仍在等待的维护线程；重复周期为零会被拒绝，避免失控忙循环。`--once` 和调试协议兼容矩阵不触发该清理。

自动化除数据层矩阵外，还覆盖首轮前停止零清理、首轮故障后继续下一轮、零周期拒绝、全新库增量模式、旧库不转换、未知v0外部表不改写、页数硬上限和真实 `yuanyuan-ai.exe` 子进程生命周期。真实子进程证明双管道可在首轮清理前健康，过期进度事件在5秒后被删除，随后健康检查与优雅退出仍成功。一年等价隔离负载的完整结果见`P0_TASK_RETENTION_LOAD_QA_2026-08-06.md`。
