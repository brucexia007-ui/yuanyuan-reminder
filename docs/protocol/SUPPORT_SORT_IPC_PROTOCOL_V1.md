# “理一理”独立本地请求协议 v1

状态：P0 Schema、纯Rust校验、AI进程内可信分发、独立有界且带3秒硬截止的命名管道原语、私密会话引导、AI监听循环、稳定核心类型化内部请求及未注册面板命令门已实现；尚未注册Tauri命令或接入真实Provider。<br>
日期：2026-08-07<br>
实现：`src-tauri/crates/yuanyuan-protocol/src/support_sort_ipc.rs`、`src-tauri/crates/yuanyuan-ai/src/support_sort_host.rs`、`src-tauri/crates/yuanyuan-ai/src/support_sort_bootstrap.rs`、`src-tauri/crates/yuanyuan-bridge/src/windows_named_pipe_server.rs`

## 1. 为什么必须独立

现有“圆圆AI控制协议v1”只负责健康检查和优雅关闭，成功响应固定为8字节ACK；任务事件管道只接收经过认证的任务状态。两者都不得承载用户倾诉正文或Provider结果。

“理一理”因此使用独立、显式版本化的请求/响应协议，不复用或扩写旧控制通道。当前已有不可达的单请求传输原语，但AI主循环没有创建该监听端点，仍不表示生产传输已经开放。

## 2. 信任边界

每个请求都包含：

- `protocol_version=1`；
- 受限ASCII `request_id`；
- 64位大写十六进制 `session_binding`。

`session_binding`必须由稳定核心为本次AI进程随机生成，不得放在命令行、环境变量、日志、数据库、前端状态或WebView载荷中。稳定核心监督器现已在每个AI启动/重启epoch生成32字节系统随机值，经继承的标准输入一次性送入AI进程，读取上限1024字节；只有非敏感的`--support-bootstrap-stdin`开关出现在命令行。父进程与AI两侧对象都不派生`Debug`/`Clone`/Serde，正常释放时清零session与专用管道名。写入失败会立即终止刚创建的子进程；AI退出、启动失败、熔断、关闭或显式重启时，稳定核心持有的session会被移除。缺失、未知字段、错误版本、错误身份或超限引导都会在AI数据库与服务启动前关闭失败。强制终止后必须提供全新引导才能重启，但该证据不等于已完成崩溃转储和换页文件取证。

AI非关闭辅助路径还必须在读取上述私密引导、访问本地数据根或打开数据库前通过崩溃隐私闸门：先为当前进程设置并回读WER `NOHEAP`，再只读检查64位HKLM中的全局LocalDumps值和`yuanyuan-ai.exe`专属子键；策略不可用、读取失败或发现配置时关闭失败。每次已认证Support Sort连接还会在客户端进程身份核验后、正文缓冲分配和读取前重新执行同一策略；拒绝会关闭监听且不消费调用者正文。该控制只缩小WER堆采集暴露面，不覆盖检查后的竞态、管理员调试器、外部转储工具、页面文件/休眠文件，也不替代真实强退取证。完整证据见`../P0_AI_CRASH_PRIVACY_GATE_2026-08-07.md`。

非默认强退取证路径使用独立target中的QA注入版release AI：只有在同一IPC协议完成Provider描述、一次性授权并收到运行时动态金丝雀正文后才异常终止；在线捕获扫描隔离应用目录、标准流和操作员声明完整的专用转储根。最终证据还必须在隔离主机停机后提供至少一个页面文件副本，并对休眠文件和交换文件逐项声明关闭/不存在或提供副本；终结器重新绑定当前源码、捕获报告和每个离线文件SHA-256后复扫UTF-8/UTF-16LE金丝雀。该工具已实现且正式AI二进制排除注入标记，但尚未取得隔离主机执行报告，见`../P0_CRASH_PRIVACY_FORENSIC_QA_2026-08-08.md`。

独立命名管道继续使用当前用户DACL和`PIPE_REJECT_REMOTE_CLIENTS`，并在读取正文前先取得客户端PID、打开对应进程、核对创建时间与退出时间，再次取得管道端点PID；前后PID、期望PID和句柄身份必须全部一致，进程已经退出、PID改变或创建时间不符均关闭失败。AI还会在数据库和服务启动前枚举自己的直接父进程，要求其PID与创建时间精确等于引导绑定的稳定核心；转交给另一启动器的引导关闭失败。稳定核心在创建监督器前新增离线签名启动门：主程序与固定相邻AI必须同时通过WinTrust链、精确发布者和签名证书DER SHA-256策略，两个已验证文件句柄在监督周期内拒绝共享写入/删除以关闭验签后替换窗口。编译期策略目前明确关闭，因此未签名原型不会被正式入口启动。逻辑竞态矩阵、真实已退出句柄和同用户非授权进程拒绝已经通过；PID复用压力执行器在第424次创建观察到同PID不同创建时间，并由独立验证器证明旧身份在载荷读取前被精确拒绝。真实同证书签名/包身份正向证据和第二Windows账户测试尚未完成，因此不得注册产品入口。

传输层等待必须服从调用者生命周期预算。稳定核心的健康探测以当前启动截止前的剩余时间调用有界双向传输，单次最多50毫秒；关闭请求同样有硬截止，不能因管道实例暂时不存在而突破监督器时限。默认控制客户端继续保留兼容入口，但监督器不得使用其1秒默认连接预算。

请求、命令、响应和结果Rust类型不派生可能扩散正文或令牌的`Debug`或`Clone`。通用Provider请求、原始Provider输出、授权能力、已授权调用及四格内部结果同样不派生自动`Debug`；仅授权能力和调用保留固定`[REDACTED]`调试格式。session binding、授权令牌、Provider身份/指纹、用户正文、原始模型输出、解析显示文档、四格结果和Support Sort专用收发缓冲在正常释放、过期、取消或全撤销时主动清零。十二段内部生产链（含崩溃隐私策略、命名管道预读闸门和语义预审门）的源码回归禁止`tracing`、`log`、标准输出/错误输出和`dbg!`；解析、传输和清零路径仍不得记录原始JSON或上述字段。主动清零用于缩短普通堆内存残留窗口，不等于对编译器临时副本、操作系统管道缓冲、崩溃转储或换页文件作取证级保证。

## 3. 请求顺序

### 3.1 `describe_provider`

只包含本机/云端去向。AI进程从可信Rust注册表选择当前Provider，并返回身份、指纹、可见名称、披露版本、披露摘要、保留说明和可选HTTPS政策链接。前端不能提交Provider显示名称或保留说明覆盖注册表。

### 3.2 `issue_authorization`

用户看完上述披露并明确确认后，稳定核心回传刚才看到的去向、Provider身份/指纹、披露版本及披露摘要，并设置`user_confirmed=true`。AI进程必须与当前可信注册表逐项复核后才签发五分钟、单次使用的授权。

该命令没有用户正文字段；未知字段和提前附带的正文直接拒绝。

### 3.3 `submit`

只允许：

- 一次性授权令牌；
- 授权绑定的去向、Provider身份/指纹和披露版本；
- 本次`user_entered_text`。

任务、任务正文、历史倾诉、记忆、文件、工作区、剪贴板、URI、脚本和任意上下文均没有Schema入口。正文上限16 KiB；空白、NUL及Unicode双向格式控制符在传输前关闭失败。

### 3.4 `cancel` / `revoke_all`

`cancel`只撤销指定一次性令牌，`revoke_all`用于窗口关闭、AI进程停机或会话失效。它们不携带正文。

## 4. 响应白名单

响应只允许以下固定结果：

- `provider_description`；
- `authorization_issued`，且必须`one_use=true`；
- `sort_completed`，只含“事实、感受、可控、下一步”四个非空字段；
- `cancelled`或`revoked_all`；
- `rejected`加固定错误码，不含Provider错误正文或诊断细节。

`sort_completed`不包含通用`response_intent`、显示文档外壳、模型动作、引用或猫咪对白。传输Schema中每个四格字段上限1 KiB；Provider专用语义门进一步限制事实/可控/下一步各512字节、感受256字节、总计1,536字节，并拒绝固定语义红线。该门仍须由真实Provider金标准评测和专业复核补全，见`../P0_SUPPORT_SORT_SEMANTIC_PRE_REVIEW_2026-08-08.md`。

## 5. 体积与兼容

- 请求最大20 KiB；
- 响应最大16 KiB；
- 未知字段、错误命令形状、非法标识、错误版本、非法URL和超限内容全部拒绝；
- v1只接受精确版本1，不猜测兼容；
- Provider政策链接只接受无用户信息、无片段、纯ASCII的HTTPS URL；链接来源仍必须是可信注册表。

## 6. 当前自动证据

9项协议纯Rust回归覆盖：

- 提交字段白名单与额外上下文拒绝；
- 授权前正文拒绝；
- session、Provider、披露摘要和明确确认必需；
- 正文大小、NUL和双向控制符拒绝；
- 版本、令牌、标识和总消息大小边界；
- 四格响应不暴露通用模型字段；
- Provider披露身份与HTTPS政策链接校验；
- 单次授权响应和四格非空约束。
- 请求session/令牌/正文及四格结果的显式清零路径；敏感协议类型没有通用克隆接口。

AI进程内另有10项可信宿主与监听回归：

- Provider适配器由可信Rust注册表提供，查询披露和签发阶段不创建适配器；
- 披露摘要由宿主对去向、身份/指纹、版本、可见名称、保留说明和政策链接做域分隔SHA-256，不接收前端自报摘要；
- session不一致不能查询或签发；
- Provider或披露变化不能签发，可信配置替换会撤销全部旧授权；
- 正常查询、确认、签发和提交只返回四格；
- 重放、取消和全撤销不会再次创建适配器；
- 原始JSON中的未知上下文字段在接触注册表、授权门或适配器之前被拒绝；原生Windows客户端写入半段JSON即关闭，或写完合法请求后不读取响应即关闭，均不会形成成功且监听器随后重绑。
- 真实命名管道往返只接受绑定PID与创建时间的客户端，并返回有界Provider披露。
- 慢Provider占用单实例时第二请求按自身预算超时；首个调用者断开或AI停机都会触发Provider取消，随后服务可重新绑定并继续处理请求。

分发器在正文校验和一次性授权消费完成后才调用适配器工厂，因此过期、重放、Provider变化或非法正文不能初始化网络传输或读取Provider凭据。Bridge另有23项Windows命名管道单元回归与1项真实同用户独立进程回归，其中覆盖精确客户端身份、直接父进程身份查询、PID查询前后不一致关闭失败、已退出进程句柄与同账户非授权进程拒绝、有界双向响应、伪造PID/创建时间在读取前拒绝、超限响应拒绝、静默服务端在调用者硬截止内返回`Timeout`、连续消息在服务端重建管道实例的短暂间隙内不丢失，以及策略闸门在身份核验后、正文分配和读取前关闭失败。私密引导有3项单元回归与5项真实AI子进程回归，覆盖随机往返、畸形/超限关闭失败、有效启动、无引导不启动、非父进程身份在数据库启动前拒绝、强制终止后只能使用新session重启，以及正文金丝雀经过固定Provider后不进入子进程标准流和隔离本地文件。

语义预审另有5项固定规则/版本化语料回归，Provider结果门共12项并覆盖合法结构中的有害语义拒绝和被拒绝解析文档的完整文本清理。该自动门仅作为专业预审输入，不把关键词规则描述为完整语义分类器。

稳定核心监督器已接入私密引导的生成、传送、epoch持有与清除，并提供只接受类型化命令、由监督器内部注入session与管道名的请求端。AI在控制健康门开放前先绑定引导指定的Support Sort管道；监听器只允许一个服务实例并串行处理请求，不分配请求队列，畸形输入丢弃后重绑，空闲或管道I/O中的停机通过`CancelSynchronousIo`唤醒并等待线程清场。真实AI子进程已完成一次无Provider查询并返回固定不可用，稳定核心类型化请求也已用精确正文金丝雀贯通固定Provider且捕获日志零命中。未注册面板门只接受`panel`窗口，外部Schema没有请求标识、session、工作区或历史入口，请求标识由稳定核心生成；该模块没有Tauri命令标记且未加入`generate_handler!`，正式安装包也不收录AI。客户端以非阻塞消息模式轮询，将连接、完整写入和有界响应读取限制在同一个3秒截止内；超时关闭客户端句柄后，AI通过非消费式`PeekNamedPipe`探测断连并触发Provider取消令牌，AI停机标记同样进入该取消条件。回归证明遵守取消令牌的慢Provider停止并且服务恢复；这不替代未来真实Provider对取消语义的独立契约验收。
