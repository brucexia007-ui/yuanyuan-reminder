# 任务事件管道确认协议v1

状态：P0 Spike冻结<br>
日期：2026-08-04<br>
对应实现：`src-tauri/crates/yuanyuan-bridge/src/windows_named_pipe.rs`、`windows_named_pipe_server.rs`

## 目的

命名管道的写入成功只表示Windows接受了字节，不表示圆圆已完成认证、nonce登记和持久化。确认协议把Bridge的“送达”边界推进到接收端完成安全提交之后，关闭“写入成功、处理前崩溃”的静默丢失窗口。

## v1帧

接收端成功提交后返回固定8字节ASCII：

```text
YYACK001
```

v1不返回错误正文、任务内容或诊断信息，避免向Hook输出敏感数据或形成反向控制通道。未知、截断、超时或连接关闭都不是成功ACK。

## 状态规则

1. 客户端连接当前用户专用、拒绝远程访问的双向命名管道；
2. 客户端以单条消息写入不超过64KiB的原始已签名事件；
3. 接收端读取完整消息，完成协议与HMAC校验；
4. 接收端在同一提交边界内原子登记nonce并持久化已接受事件；
5. 只有第4步成功后才能写回`YYACK001`；
6. 客户端只有精确读取8字节ACK才报告送达；其余结果进入受限暂存并保持fail-open；
7. 整条客户端路径仍受3秒进程级硬超时约束。

## 当前边界

客户端ACK校验、双向安全管道、服务端显式`acknowledge()`、独立AI任务库原子提交以及`YuanyuanAI.exe`的“提交后ACK”接收循环已经实现，并覆盖合法/无效事件、连续连接和优雅停机测试。AI进程仍缺主程序监督、崩溃熔断、版本协商和发布集成，因此该协议仍处于P0验证阶段，不代表任务守望已可发布。
