# 圆圆连接器信任与密钥生命周期 v1

状态：P0 已实现、真实 Hook 尚未启用  
日期：2026-08-04  
实现：`src-tauri/crates/yuanyuan-bridge/src/trust_store.rs`、`credential_trust.rs`、`windows_credentials.rs`、`authentication_health.rs`，以及稳定核心 `src-tauri/src/connector_trust_control.rs`、`connector_discovery.rs`

## 目标与边界

本协议管理本机任务守望连接器的事件认证身份。每个 `connector_id + source_instance` 都拥有独立高熵密钥；密钥正文只存在于当前 Windows 用户的 Credential Manager，SQLite 只保存不可用于签名的身份、`key_id`、状态、时间和类型化审计。

当前控制面只把随产品注册的 `builtin.codex` 与 `builtin.claude-code` 用作首次注册的实现选择器。预览首次注册时，稳定核心同时生成 `<实现选择器>.<随机 UUID>` 形式的稳定 `connector_id` 和独立 UUID `source_instance`；后续轮换、重置、重连与状态查询必须携带这组完整身份。最多保留 16 个信任身份和 16 个尚未消费的确认操作。未知连接器、无效实例、容量溢出、数据库缺失/损坏/忙碌或凭据不可读全部关闭失败。

当前对外控制面不安装、合并、覆盖或删除 Codex/Claude Code Hook 配置，信任控制返回值固定包含 `hookConfigurationChanged=false`。稳定核心内部另有不可从 Tauri 或设置页调用的写入事务原型及官方目标封装，已在临时目录验证授权重读、官方路径解析、全部用户级来源绑定、无损候选、摘要确认、备份与原子替换；这不改变对外零写入事实。真实连接仍需工具自身信任审核、用户可见确认和仅撤销圆圆片段的流程。

## 存储所有权

- 信任库：`%LOCALAPPDATA%\Yuanyuan\connector-trust.sqlite3`；稳定核心是唯一写入者，Bridge 与 AI 只读；目录和数据库应用当前用户 DACL；父路径必须是真实目录，数据库必须是普通文件，目录替代、文件符号链接和父目录符号链接在 SQLite 打开前拒绝。
- 认证健康库：`%LOCALAPPDATA%\Yuanyuan\connector-authentication-health.sqlite3`；只保存身份、连续失败次数和固定时间，不保存密钥、载荷、路径或错误正文。
- 密钥目标：`Yuanyuan/TaskEventKey/<key_id>`；生产使用 `CRED_PERSIST_LOCAL_MACHINE`，可供同一 Windows 用户在本机后续登录会话使用。
- 密钥：32 个由操作系统随机源生成的字节。写接口不返回、导出或记录密钥正文。
- `key_id`：`yy.g<generation>.<128-bit random hex>`，不是秘密，但一经使用永久进入墓碑表，不得重用。
- 信任审计：只允许固定动作、固定原因、连接器身份、`key_id` 和 Unix 毫秒时间；没有正文、错误消息、密钥或载荷列。

固定原因只有：首次连接、用户主动、连接器重新配置、连接器重装、来源实例变化、疑似泄露、凭据缺失、宽限到期；旧开发库迁移行固定标记为 `legacy_migration`。

## 首次连接

1. 稳定核心验证内置实现选择器、当前状态和容量；被动安装发现不创建实例身份。
2. 用户先查看变更预览；首次授权由核心生成随机稳定 `connector_id` 与独立随机 `source_instance`，随后签发绑定动作和完整身份的随机确认令牌，令牌两分钟过期且只能消费一次。固定实现选择器不会持久化为新身份，也不会进入 Hook 所有权参数。
3. 核心生成从未使用过的随机 `key_id`，确认目标不存在，再向 Credential Manager 写入随机密钥。
4. 核心在一个 `BEGIN IMMEDIATE` 事务中写入信任身份、永久 `key_id` 墓碑和类型化审计。
5. 若事务失败，核心只删除刚创建的精确凭据目标；不会覆盖或枚举其他凭据。

## 两阶段轮换

1. 只有活动身份且没有尚待清理的旧密钥时可以开始轮换。
2. 新凭据先写入 Credential Manager；信任事务提交后，新 `key_id` 才成为活动密钥。
3. 旧 `key_id` 成为 previous，记录 `switched_at` 与最长五分钟的 `grace_expires_at`。
4. 新密钥只对完全匹配的 `connector_id + source_instance` 有效。
5. 旧密钥只接受 `signed_at <= switched_at` 且 `now <= grace_expires_at` 的事件。切换后才生成的旧密钥事件即使仍在五分钟内也拒绝。
6. 宽限到期后先从信任库移除旧权限并提交审计，再删除精确凭据。删除失败最多留下无法获得认证权限的孤立凭据，不恢复旧权限。

Bridge 在把原始 Hook 载荷签名之前校验该身份的当前活动密钥；AI 和 Bridge 在验签时再次绑定事件内的连接器身份、签名时间与当前时间。仅知道其他连接器的 `key_id` 或持有同一用户下另一实例的密钥，不能跨身份签名。

## 重置与重新连接

- “重置连接器信任”不使用宽限：信任事务先立即清空活动/旧密钥权限并写入撤销时间，之后才逐一删除精确凭据。
- 删除失败不会回滚撤销；事件验签仍拒绝。
- 重新连接必须生成全新的随机 `key_id`，代次递增，任何历史 `key_id` 都不能复用。
- 状态查询不创建目录或数据库，不返回活动/旧 `key_id`，只返回稳定 `connector_id`、是否已配置、是否活动、是否需重新连接、是否仍在轮换宽限、代次、`source_instance` 和是否为历史身份。
- 早期开发记录若把固定实现选择器误存为 `connector_id`，发现时只读标记为历史身份并要求重连；历史身份不得轮换或原地重连，也不得写入未来 Hook。当前实现不静默搬迁旧密钥或伪造新的身份连续性。

## 断开与配置撤销

私有断开预览只接受活动随机连接器身份，内部解析官方用户级来源并生成当前预期 handler；确认只接受两分钟单次令牌。自动撤销只删除所有权字段与规范原始节点字节都精确匹配的圆圆 handler：单-handler圆圆组可以整组移除，混合组保留用户 handler，任何注释、重格式化、额外字段、重复或跨来源变化都会停止。执行仍使用同目录精确备份、文件身份复核和原子替换。

正式控制面必须把“配置撤销”和“认证权限撤销”显示为两个有顺序但可独立恢复的结果：

1. 默认先尝试配置撤销，成功后立即执行信任重置；信任重置失败时 Hook 已移除但权限记录可能仍活动，界面必须持续提示重试撤销权限；
2. 配置被用户修改而无法自动删除时，不得因此阻止用户单独立即重置信任；重置后残留 Hook 无法取得有效密钥或通过认证，但只能由用户人工复核删除；
3. 信任已撤销不能被当成删除任意相似 Hook 的授权，卸载器同样只能处理摘要未改变的圆圆片段；
4. 当前私有组合状态机已实现上述顺序、显式“仅撤销信任”模式、两分钟单次确认和分阶段结果；撤权后凭据/DACL维护另有独立确认事务，只处理信任库证明已撤销的精确凭据并记录有界重试进度；它仍没有 Tauri command、产品入口或真实配置执行路径。

## 故障与非干预

- 信任库或 Credential Manager 不可用时不读取空值、旧缓存或降级密钥。
- 普通解析器不能绕过带身份与时间的授权读取；生产验签使用 `TrustEnforcingKeyResolver`。
- 认证失败不进入任务状态机、不暂存未认证载荷；Bridge 仍保持空输出和退出码 0，不改变源任务结果。
- 同一已授权身份在十分钟内连续三次可归属认证失败后，只暂停圆圆接收该身份事件；未知身份/密钥不计数，普通成功不能解除已暂停状态，显式授权变更成功后才清除暂停。
- SQLite 事务失败时信任、墓碑和审计整体回滚。撤销后的凭据清理失败与新建事务回滚后的凭据清理失败使用不同的固定错误类型。
