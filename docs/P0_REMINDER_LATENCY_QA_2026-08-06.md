# P0提醒端到端延迟验收设计（2026-08-06）

## 结论

已修复运行验收版误用开发服务器、隐藏窗口和固定标题提前命中的验收缺陷，并在可交互 Windows 桌面完成20个真实窗口样本；5个调度相位各重复4次，20/20通过。AI关闭、暖系统、隔离运行验收版的首个阈值门已经冻结并通过；这关闭了P0-003的暖系统提醒延迟基线缺口，但仍不是正式默认二进制、长期常驻、睡眠恢复或签名候选的发布基线。

- 后端领取延迟：P50 `6,903.5 ms`，P95 `12,938.9 ms`，冻结上限 `16,000 ms`；
- 后端到窗口交接：P50 `240.9 ms`，P95 `281.0 ms`，冻结上限 `1,000 ms`；
- 计划时间到窗口呈现：P50 `7,150.2 ms`，P95 `13,167.8 ms`，冻结上限 `17,000 ms`。

采样器没有在正式前端增加回传代码，也不读取正式用户数据库。它只在非默认`runtime-qa`编译功能中创建隔离数据根、合成单次事项并记录三个时间点：

1. `scheduledAt`：合成事项计划到期时间；
2. `claimedAt`：生产`Repository::claim_due`真正插入occurrence的`created_at`；
3. `presentedAt`：Windows UI Automation首次在真实猫咪窗口可访问性树中发现该事项名称的时间。

据此分别计算后端领取延迟、端到端呈现延迟和后端到窗口的交接延迟，并使用最近秩法生成P50/P95。可访问性树每50 ms轮询一次，因此呈现时间最多包含约50 ms探测误差。

## 运行方法

```powershell
npm.cmd run runtime:qa:build
npm.cmd run runtime:reminder-latency -- -SampleCount 5 -ExitAfterSeconds 30
npm.cmd run runtime:reminder-latency:gate
npm.cmd run runtime:reminder-latency:verify -- --report <绝对报告路径>
```

`runtime:qa:build`会先构建生产前端资源，再为验收版启用Tauri `custom-protocol`。直接运行不带该协议的`cargo build`会让WebView访问`localhost`，只能得到`ERR_CONNECTION_REFUSED`页面，不能作为真实前端验收。

每个样本使用新的带标记隔离目录。应用窗口完成创建后才写入合成事项，事项到期偏移依次为2、5、8、11、14秒，以覆盖15秒调度周期的不同相位。每次应用通过自身退出路径返回0；脚本只在失败兜底时结束自己启动的精确进程。无论通过或失败，目录都必须经过父目录、叶子名和标记内容三重校验后才能递归删除。

默认5个样本只用于确认链路和得到初始分布。基线门固定运行20个样本并启用`BaselineGate`；少于20个样本、任一P95超过冻结上限或任一样本失败都会令报告`ready=false`并返回2。冷启动、长期常驻、睡眠唤醒、锁屏恢复和签名候选仍需分别记录，不能把暖系统结果外推到所有场景。

独立Node校验器不信任报告中的`ready`或汇总值：它重新计算逐样本三段延迟和最近秩P50/P95，核对20样本五相位序列、唯一提醒/无障碍名称、严格字段集合、冻结阈值与限制声明，并将报告内三项SHA-256重新绑定当前验收主程序、夹具和采样脚本。报告必须是验收证据目录中的普通文件；过期二进制、脚本变化、路径逃逸、未知字段或乐观篡改都会关闭失败。UTF-8及Windows UTF-8 BOM两种报告编码均有回归覆盖。

## 自动关闭条件

任一条件不满足，报告`ready=false`并以退出码2结束：

- 30秒内没有出现`exit-scheduled`阶段证据；
- 合成事项无法写入隔离数据库；
- 到期后20秒内没有在真实Windows可访问性树找到事项；
- 应用没有按时通过受控路径以退出码0结束；
- 数据库中没有与该事项对应的实际领取记录；
- UI呈现时间早于后端实际领取时间；
- 任一隔离目录未被安全清理；
- 通过样本数少于请求样本数；
- 基线模式少于20个样本，或后端/交接/总呈现P95分别超过16,000/1,000/17,000 ms。

脚本使用独占运行锁阻止两个采样批次并发；每个样本生成唯一测试标题，并只匹配强提醒按钮的完整无障碍名称，避免把任务列表、上一样本或另一进程中的固定标题误认成当前提醒。

## 已验证的非窗口部分

- Rust定向测试使用生产`claim_due`链路，证明测试专用到期覆写会生成pending occurrence，并保存计划时间与实际领取时间；每个样本标题和强提醒无障碍名称均唯一；
- 运行配置只接受`task-watch`、`baseline-ai-off`和`reminder-latency`，未知值关闭失败；
- 通用夹具只接受绝对、固定前缀、精确标记且非重解析的隔离根；
- PowerShell脚本语法解析通过；独占锁回归证明第二批次在启动窗口前关闭失败，失败样本能够生成结构化报告、返回2并清理进程/目录；
- 独立报告校验器5项测试通过，覆盖Windows BOM、样本/相位缺失、乐观状态、时间与延迟篡改、P50/P95与阈值篡改、来源绑定过期、重复强提醒名称和未知字段；
- 默认正式主程序的二进制边界扫描覆盖8个运行验收标记，并另覆盖3个数据库迁移验收标记；任一测试配置、临时前缀或夹具名混入即阻断预检。
