# P0 任务事件一年等价负载验收（2026-08-06）

## 结论

一年等价的固定合成负载已经通过生产清理与有界增量回收：

- 3,650个任务，按每天10个任务建模；
- 每个任务48条状态事件，共175,200条事件；
- 3,650个过期nonce和3,650个当前nonce；
- 数据年龄覆盖0—399天，以跨过7/90/180/365天全部边界；
- 118个有删除周期后到达固定点，另含一次零删除确认；
- 删除171,287条事件、1,148个任务和3,650个过期nonce；
- 保留2,502个任务、3,913条事件和全部3,650个当前nonce；
- 最新事件存在、无可继续删除行、行数差值与生产返回值一致、固定合成内容边界全部通过。

验收只使用随机临时AI数据库，不读取提醒库、正式AI库、任务标题、项目路径或任何用户数据。临时目录带精确所有权标记并在报告写入前删除；报告不含临时路径且只能写入新的绝对JSON文件。

## 首轮发现与修正

首轮同负载逻辑清理正确，但SQLite为`auto_vacuum=none`：检查点后数据库家族仍为32,903,168 bytes，其中7,382页、约30.24 MiB处于空闲列表，占92.17%。这证明“删除记录”不等于“长期磁盘增长已解决”。

据此冻结以下工程策略：

- 只有全新、`user_version=0`且不存在未知用户表的AI库，才在任何迁移建表前启用`auto_vacuum=INCREMENTAL`；
- 每个发生逻辑删除的维护周期随后逐页回收，最多256页，无进展立即停止；
- 增量回收在删除事务提交之后执行，失败不伪装成删除回滚；
- 旧AI库、未知v0外部表和`auto_vacuum=none`数据库保持原格式，不在普通升级中静默执行全库`VACUUM`；
- 验收程序使用独立Release目标目录，既不进入默认主程序，也不进入NSIS安装包。

直接调用一次`incremental_vacuum(256)`在本负载布局中只推进约1页，因此实现改为在同一硬额度内逐页调用并核对空闲页下降，最多256次。自动化证明32页测试额度精确回收32页，0、超过1,024页和旧库均保守拒绝或零操作。

## 尚未关闭的门

本结果证明固定合成数据上的正确性、批次收敛和新库空间回收，不证明以下项目：

- 24/72小时真实连接器持续写入下的CPU、内存、WAL和锁竞争；
- 系统睡眠、休眠和恢复正好跨越维护时点；
- 满盘、断电模拟、进程强杀和安全软件扫描中的增量回收；
- 慢速或加密磁盘上的周期耗时；
- 6小时与256页额度的真实试点体验；
- 既有`auto_vacuum=none`库的显式转换产品流程。

因此当前采用“新库有界增量回收、旧库默认不转换”的保守策略，但P0长期常驻门和P1-E02整体仍保持未完成。
