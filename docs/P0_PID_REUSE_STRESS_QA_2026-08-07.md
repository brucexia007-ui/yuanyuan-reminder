# P0 Windows PID复用压力验收（2026-08-07）

## 结论

已建立独立、非默认、不会进入正式安装包的真实进程压力执行器和证据验证器。执行器只有在Windows真实分配出“同一PID、不同进程创建时间”，且绑定旧创建时间的命名管道在读取正文前返回精确`ClientIdentity`拒绝时，才允许报告`ready=true`。普通进程轮换、逻辑模拟、手工修改报告或仅出现同一PID同一创建时间都不能通过。

2026-08-08 共享命名管道新增正文预读策略闸门后，身份实现源码哈希发生变化，旧烟测报告立即被独立验证器按设计判为陈旧。随后同一环境的256次刷新样本仍没有复用，保持`pending`。继续请求4,096次有界创建时，Windows在第424次创建出现同PID、不同创建时间；新进程使用旧身份连接后，服务端在读取载荷前精确返回`ClientIdentity`。执行器与独立验证器均退出0，最终报告`outcome=passed`、`ready=true`。因此当前源码版本的真实PID复用正向压力门已经关闭。

## 实现边界

- `yuanyuan-bridge`新增非默认`pid-reuse-qa`功能和独立`yuanyuan-pid-reuse-qa.exe`；默认workspace release和Tauri构建不会生成或收录它。
- 每个探测子进程通过继承stdin等待父进程命令；父进程在子进程存活时从真实Windows进程句柄读取PID、创建时间和退出时间，退出时间非零立即拒绝。
- 执行器只保留PID与创建时间的内存映射。只有同一PID出现不同创建时间才进入复用验证；原始PID不会写入报告。
- 复用出现时，服务端以旧PID和旧创建时间绑定当前用户专用命名管道，新进程尝试发送固定无敏感测试载荷。只有服务端在读取前返回精确`ClientIdentity`且子进程按时退出才通过。
- 所有子进程有3秒硬截止；错误路径由清理守卫终止并回收仍存活的子进程。当前烟测结束后没有残留圆圆相关进程。
- 报告只允许操作者显式提供的全新绝对`.json`路径，拒绝既有文件和重解析父目录，写入后设置当前用户专用DACL；失败只清理由本次执行创建的报告。
- 报告绑定`windows_named_pipe_server.rs`源码SHA-256。独立Node验证器要求精确Schema、冻结见证声明、真实复用、旧身份拒绝、计数关系、源码哈希和`ready=true`全部一致，并拒绝未知字段。
- 发布边界同时拒绝Tauri的`externalBin`/`resources`声明出现该执行器，并扫描默认主程序中不得出现`yuanyuan-pid-reuse-qa`标记。

## 使用方式

```powershell
npm.cmd run security:pid-reuse:qa -- --report <绝对且不存在的JSON路径> --iterations 65536 --attest-isolated-test-host isolated_windows_pid_reuse_stress_v1
npm.cmd run security:pid-reuse:verify -- --report <上一步报告的绝对路径>
```

执行器允许2至2,000,000次创建，默认65,536次。没有观察到复用属于`pending`而不是失败的安全实现错误，但命令仍返回2，防止自动流程把“未观察到”误判为通过。证据验证器只接受`passed`报告。

## 自动回归

Rust 4项：

1. 只接受完整、冻结的操作者合同和内部子进程合同；
2. 只有同PID且不同创建时间才识别为复用；
3. `ready`必须同时依赖真实复用与精确旧身份拒绝，源码哈希变化关闭失败；
4. 报告使用`create_new`且绝不覆盖既有证据。

Node 4项：

1. 只接受直接真实复用与读取前旧身份拒绝；
2. 普通进程轮换的`pending`报告不能成为证据；
3. 源码变化或乐观修改任一布尔值关闭失败；
4. 未知字段与不可能的计数关系关闭失败。
