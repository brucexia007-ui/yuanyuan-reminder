## 2. 冻结候选决定

下列项目在草案中没有“以后再说”的默认分支；只有具名评审可修改。

### 2.1 学习与呈现

- 自动邀请默认关闭；阶段 0/1 只允许用户开启后的“专注结束”触发。
- 提醒优先级和稳定 occurrence 语义不因学习修改。
- 会话 TTL 为最后活动后 24 小时，不按自然日零点过期。
- 强提醒抢占写 `interrupted` 事件并转 `paused`；提醒结束后不自动抢回前台，由用户选择继续。
- 已答记录一经事务提交不重算；未答卡在暂停、放弃和过期时不计错、不改变调度。

### 2.2 内容包 v1

- 首版输入为原生 JSON 和带字段映射的 CSV；不支持压缩包、媒体、远程 URL、脚本、模板、宏或插件。
- 已知对象未知字段一律拒绝。只有命名空间化 `extensions` 可以被不认识的客户端原样保留；通用引擎不得执行或依赖它们。
- 题型只有 `choice` 和 `recall`。选择题必须有 1 个正确答案和 1—3 个无歧义干扰项；否则降级 recall，不使用 AI 补写。
- 包内 `cardId` 只允许 `[A-Za-z0-9._:-]`，长度 1—128；规范化重复整包拒绝，不自动改名。
- 内部项 ID：`SHA-256("yuanyuan-item-v1\0" + packId + "\0" + externalCardId)`。
- 同时保存 `prompt_sha256`、`answer_sha256`、`content_sha256` 和发布者 `schedule_epoch`。题干变化、答案变化或 epoch 增长都进入保守差异处置，不静默保留进度。

### 2.3 安全预算

| 项目 | 冻结候选 |
| --- | --- |
| JSON/CSV 总字节 | 25 MiB，解析前拒绝超限 |
| 单包卡片数 | 20,000 |
| JSON 深度 | 8 |
| 同时待确认预览 | 8 |
| preview token TTL | 600 秒、单次使用 |
| 远程/绝对/父目录资源 | 拒绝 |
| Unicode bidi/控制符、NUL、CSV 公式 | 拒绝 |

preview token 必须绑定完整文件 SHA-256、解析器版本、schema 版本、规范化预览结果和过期时间。确认时重新验证文件身份；替换、重放或过期均要求重新预览。

### 2.4 数据与迁移

- 最终 v6 必须在同一迁移中包含通用 `learning_items`、命名空间扩展、调度、会话事件、目标、答题、复习日志和错题队列；当前未发布的 REL-002 会话迁移只是该文件的第一部分，不得单独发布。
- `learning_items` 的通用 prompt/answer 在移除 `englishVocabulary` 扩展后仍必须可学习、可判定、可调度。
- v5 `active/interrupted/completed/exited` 分别映射 `paused/paused/completed/abandoned`；升级不自动弹小黑板。
- 迁移必须先生成可恢复备份，在一个可回滚过程内完成并输出卡/项、调度哈希、会话/答题/复习/错题计数、孤儿 FK、`integrity_check`、`foreign_key_check` 和失败恢复结果。
- 完整清库是显式用户操作；历史评分不通过 UPDATE 伪造。

### 2.5 安装与更新边界

- 预览零可见写入；确认后写同一应用数据根内 staging，完整校验后原子切换 ready。
- 新版本 ready 前旧版本继续 ready；失败、取消和崩溃不得留下半安装或破坏旧进度。
- 阶段 1 只保存未来更新所需哈希/epoch 元数据，不交付远程更新、完整差异 UI 或回滚 UI。
