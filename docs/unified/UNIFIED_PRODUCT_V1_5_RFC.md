# 圆圆提醒 v1.5 统一产品 RFC

状态：已接受，实施中  
日期：2026-08-25  
实施分支：`feat/unified-v1-5`  
公开升级基线：`v1.3.2`  
统一版本：`1.5.0`

## 1. 决策

圆圆提醒从 v1.5 起只维护一个公开产品、一条可发布主线、一个 Windows 应用身份和一个版本号。原 Stable、Learning Preview 与个人考研词库版不再作为三个并行产品迭代。

统一产品固定为：

- 产品名：`圆圆提醒`；
- 应用身份：`com.yuanyuan.reminder`；
- 首个统一版本：`1.5.0`，预发布按 `1.5.0-beta.N` 排序；
- 正式源码主线：`main`；
- 正式安装包：每个候选只允许一个圆圆提醒安装包；
- 学习能力：产品内置通用模块，不再依赖 Preview 产品身份；
- 自动学习邀请：默认关闭，只有用户明确开启后才可能运行；
- 个人内容：不得进入公开源码、Git 历史、通用安装包或候选目录，只能由用户显式导入。

旧 v1.4.0 Stable-only 范围、Stable/Preview 双构建和个人版安装包作为历史证据保留，但不再定义 v1.5 产品形态。所有候选绑定报告必须针对新的统一二进制重建，不能沿用旧安装包哈希。

## 2. 为什么使用 v1.5.0

公开最新版为 v1.3.2；v1.4.0 虽未公开发布，但仓库已经用它冻结过“稳定版源码不得包含 Learning Preview”的发布合同。统一产品反转了该合同。继续复用 v1.4.0 会让旧范围报告、旧默认关闭门和新统一候选共享同一版本号，增加误发风险。

v1.5.0 表示一次向后兼容的产品范围扩展，不表示删除提醒、喝水、专注、休息或桌宠能力。升级必须保留 v1.3.2 用户数据。

## 3. 源码与分支边界

统一实现从已审计且无个人内容的 `feat/fragment-learning-stage-0-1` 末端创建。当前实施分支为 `feat/unified-v1-5`。

- `feat/learning-preview-foundation`：只保留历史引用，停止继续开发；
- `personal/kajweb-kaoyan-local`：保持私有历史，不直接 merge；
- 私人分支仍有价值的通用修复只能逐文件审计后重写或挑选，不能携带个人资源、个人构建入口或受限内容历史；
- `release/low-cost-beta`：保留 v1.4.0 历史，不承接 v1.5 开发；
- v1.5 通过全部门后，`main` 只接收统一产品提交。

## 4. 构建与运行合同

### 4.1 单一正式构建

正式 `npm.cmd run tauri build` 必须生成唯一产品身份 `com.yuanyuan.reminder`。生产运行时不得因学习模块存在而把身份改为 `com.yuanyuan.reminder.learning-preview`。

独立 runtime-QA 身份和隔离数据根可以继续存在，但它们是测试夹具，不是可安装产品版本。

### 4.2 学习模块

统一正式二进制编译通用学习模块和命令。前端不再通过 `learning-preview` Vite mode 决定是否包含学习页面。

产品默认行为仍然克制：

- 手动学习入口属于统一产品；
- 自动邀请默认关闭；
- 不包含个人词包或官方考研词包；
- 用户未首次进入学习或导入内容前，不创建学习数据库；
- 学习数据库不可用时，提醒核心、桌宠、喝水、专注和休息继续可用。

### 4.3 唯一版本来源

根目录 `product-version.json` 是产品名称、身份、版本和内容政策的机器权威。`package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 和 `src-tauri/tauri.conf.json` 必须通过同步器与它保持一致。

任何文件名单独改成 `1.5.1` 而内部元数据仍是 `1.5.0` 都必须失败关闭。

## 5. 数据合同

统一产品继续使用两个故障域：

- 主提醒库：`yuanyuan-reminder.sqlite3`，统一版本支持 schema 12；
- 学习库：`learning-data/yuanyuan-learning.sqlite3`，当前 schema 6。

它们属于同一个产品的备份、恢复、导出和删除体验，但学习库损坏或迁移失败不能阻止主提醒库启动。

必须实现四条来源路径：

1. 公开 v1.3.2 Stable 数据原地升级；
2. 本地 v1.4.0 Stable 数据原地升级；
3. `com.yuanyuan.reminder.learning-preview` 旧数据只读发现、预览和显式迁移；
4. `com.yuanyuan.reminder.learning-personal` 旧数据只读发现、预览和显式迁移。

旧 Preview/个人目录不得在迁移成功后自动删除。迁移必须先备份、事务提交、重开核验、记录幂等凭证，再允许用户显式归档或删除旧目录。

个人 4,533 卡内容不得由安装器搬入统一产品。若用户拥有相应本地内容，只能通过原生 JSON、CSV 或后续固定 `.yuanyuan-learning-pack` 导入合同进入，来源责任继续归用户。

## 6. 质量门变化

v1.4 的“默认产物不得出现学习命令”门在 v1.5 中废止，替换为统一产品门：

- 唯一产品身份和版本一致；
- 正式二进制包含通用学习能力；
- 无个人路径、个人 edition 标识、个人内容或受限来源字节；
- 自动邀请默认关闭；
- 首次学习前学习库零创建；
- 学习库失败不影响主提醒库；
- v1.3.2、v1.4 Stable、Preview 和个人版迁移矩阵通过；
- 候选目录只有一个安装包，并绑定提交、配置、哈希和签名状态；
- 签名、SmartScreen/第三方安全软件、升级回退、许可证、无障碍与真实 Windows 人工门针对精确统一候选重新完成。

## 7. 发布节奏

1. `1.5.0-alpha.N`：内部迁移和故障隔离验证；
2. `1.5.0-beta.N`：单一产品安装包，学习仅手动入口，无内置词包，自动邀请关闭；
3. `1.5.0-rc.N`：冻结签名候选，停止数据库和安装身份变化；
4. `1.5.0`：全部自动门、人工 Windows QA、签名和发布签字通过后发布。

任何阶段出现提醒核心回归、旧数据不可逆变化、私人内容进入候选或学习模块导致主程序无法启动，都回退到上一不可变候选，不通过隐藏入口掩盖。

## 8. 完成定义

只有下列事实同时成立，项目规整才算完成：

- 仓库默认构建就是统一 v1.5 产品；
- 不再存在可发布的 Preview/Personal 产品配置或脚本；
- `main` 是唯一长期可发布主线；
- 四条数据升级/迁移路径有自动证据和真实 Windows 复核；
- 唯一候选目录合同通过；
- 旧双构建、旧默认关闭与旧 v1.4 候选文档均被标记为历史；
- v1.5 精确候选完成现有发布门，不复用旧哈希或人工签字。
