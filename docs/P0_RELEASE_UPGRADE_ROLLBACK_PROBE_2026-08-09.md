# P0 发布安装、升级与安全回装旧版隔离探测

日期：2026-08-09  
对应范围：P0-E08 安装/升级/卸载/回退工程证据的可自动化子集

## 结论

`npm.cmd run release:upgrade-rollback` 已在当前独立 Windows 测试账户完成一轮候选绑定正向探测：官方 v1.3.2 Setup → 当前 v1.4.0 NSIS → 卸载 v1.4.0 → 回装官方 v1.3.2 → 卸载 v1.3.2。两次旧版安装、当前版升级、两次卸载均返回 0；每一阶段的实际主程序版本、字节数和 SHA-256 都与冻结身份精确一致。

该项是独立的 `isolated_installer_transition_probe` 自动门，不等同于完整 `upgrade_rollback_drill`。默认安装目录文件转换、损坏候选/主程序替换受阻、部分主程序写入后的受限Job终止与恢复、合成全新数据库首次启动恢复，以及卸载数据选择现均已作为独立门通过；预检另列 `default_install_control_panel_registration=pending`，当前为 13 项通过、13 项待完成、0 项失败，`readyForRelease=false`。签名候选、控制面板注册、真实 v1.3.2 业务数据库迁移、真实掉电/系统重启及外部干净机矩阵仍必须另行完成。

- 所有安装文件位于带随机运行号和所有权标记的一次性当前用户目录；
- v1.3.2 初装与回装后的主程序均为 20,574,720 bytes、版本 1.3.2、固定历史哈希；
- v1.4.0 阶段的主程序精确等于当前 `nsis_installed_core`，四份许可证文件集合及内容哈希全部匹配；

## 当前账户的注册观察

当前测试账户在 `/S /D=<一次性目录>` 的三次安装中均未向当前进程可见的每用户注册位置暴露产品注册；安装文件、卸载器和快捷方式仍正常生成。报告将三个阶段如实记录为 `registrationDisposition=absent`，并只接受三个阶段一致的 `owned` 或 `absent` 状态，混合/部分注册会失败。

因此本证据不宣称“控制面板注册升级通过”。默认安装路径文件转换已另行取得正向证据，但同一受管账户禁止 HKCU 写入，报告保持 `registrationGatePassed=false`，见 [默认安装路径验收](P0_RELEASE_DEFAULT_INSTALL_PATH_QA_2026-08-09.md)。正式演练仍须在允许 current-user 注册写入的干净普通账户验证控制面板条目、版本、安装位置、启动项、快捷方式和卸载选择；该限制保留在人工 `upgrade_rollback_drill` 门中。

## 不覆盖的正式门

- 已签名历史版与当前候选的发布者、证书、时间戳和信任链；
- 真实控制面板注册和交互式安装/卸载选择；默认安装路径的静默文件转换已另行通过；
- 真实历史数据库迁移前后的强制中断，以及安装写入或数据库迁移期间的真实掉电/系统重启；损坏包、主程序替换受阻、受限Job中的部分主程序写入终止和合成全新数据库首次启动恢复已由独立子门覆盖；
- 来源可确认的 v1.3.2 真实业务数据库迁移、备份、恢复及旧版兼容策略；
- Defender、SmartScreen、两款第三方安全软件与真实 Mark-of-the-Web；
- 真实用户唯一数据副本。探测不会读取、复制或修改现有用户数据库。

只有上述矩阵、人工证据和严格发布门全部通过后，才能把 `upgradeRollbackDrillVerified` 置为 `true`。
