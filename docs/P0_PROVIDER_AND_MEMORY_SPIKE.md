# P0 Provider 与中文记忆检索 Spike 报告

日期：2026-08-04；状态：部分完成，不能作为 v2.0B 可用声明。

## Provider 契约结果

`yuanyuan-ai` 已增加厂商无关的 Provider Adapter 契约。宿主拥有结构化输出校验、输入上限、100 ms—120 s 超时、主动取消、事件背压、用量声明核对和终稿唯一性；适配器只负责传输转换。

流式通道只允许阶段、用量和最终结构化结果，不把自由文本增量直接交给前端。终稿只能包含 `response_intent` 和可选的 `display_document`，两者继续经过协议层校验。

本地回环夹具已验证：

- 合法阶段、用量和结构化终稿；
- 调用方主动取消；
- 100 ms 看门狗超时；
- 畸形终稿、重复终稿、缺少必需能力和虚假用量能力声明关闭失败。

尚未完成一个真实云 Provider 的契约验证、网络允许列表、费用上限、凭据生命周期和服务端保留策略。因此 P0-050 仅完成回环部分。

## 中文 FTS5 对比

测试集是 6 条合成陪伴记忆，不包含真实用户倾诉。查询覆盖“开会前、加班后、喝水提醒、构建成功、连续追问、肩颈酸痛”，评价口径为 Recall@3。

| 方案 | 命中 | 结论 |
| --- | ---: | --- |
| FTS5 `unicode61`，未分词连续中文 | 0/6 | 不适合直接承担中文子串检索 |
| FTS5 `trigram` | 6/6 | 作为 P0 主索引候选 |
| 两字字面回退 | “焦虑”“加班”2/2 | 补足 trigram 无法索引少于三字符的问题 |

当前实现使用 `trigram` 主索引；少于三个 Unicode 字符的查询走上限 20 条的参数化 `LIKE` 字面扫描，`%`、`_` 和转义字符会先转义。三字以上查询被包装为 FTS5 字面短语，模型文本不能注入 `OR` 等查询语法。更新在事务中先删旧文本再写新文本，删除是显式操作。

上述6条结果只证明检索算法小样，正式金标准仍需扩大样本，并分别统计情绪偏好、任务事实、时间偏好和否定表达。记忆生命周期数据层的后续增量如下。

## 记忆生命周期增量

精选记忆生命周期由 AI 数据库 v2 引入；数据库当前已迁移到 v4（v3仅追加类型化安抚偏好并扩展墓碑类型，v4仅增加任务摘要证据投影，不改变记忆表）。v2 新增精选记忆、关系、检索使用记录、删除墓碑和正式 `trigram` 索引。低信任来源只能形成草稿；用户采纳后生成新的 `user_confirmed` 记录并保留原始生成链。冲突期间双方退出检索，过期记录移出索引，彻底删除递归清理派生/重复/替代谱系并为每个身份写墓碑。

当前墓碑可以在旧备份的临时恢复候选中先行应用，防止已删除谱系静默复活；墓碑写入失败会令正文、FTS、关系和审计删除整体回滚。详细契约见 `protocol/MEMORY_LIFECYCLE_V1.md`，备份恢复顺序见ADR-0009。

正式记忆中心UI、云上下文选择、加密备份和跨设备导入仍未实现，不能声明长期记忆已可用。

实现与可复现实验位于 `src-tauri/crates/yuanyuan-ai/src/provider.rs` 和 `src-tauri/crates/yuanyuan-ai/src/memory_search.rs`。
