# P0 AI辅助进程签名启动门证据（2026-08-07）

## 结论

AI辅助进程的正式启动入口现为“策略关闭且验证失败即不可用”。即使`yuanyuan-ai.exe`出现在主程序相邻目录，只要发布者与签名证书策略尚未冻结，稳定核心就不会创建监督线程、私密session或AI子进程。该门只完成了安全的关闭态和可测试的正向判定逻辑，不代表已有可发布的签名AI包。

## 实现边界

- `src-tauri/resources/ai-release-trust-policy-v1.json`是编译期嵌入的版本化策略；当前`enabled=false`且不包含发布者或证书值，运行时不能通过替换外部文件开启。
- `src-tauri/src/windows_artifact_trust.rs`集中实现离线WinTrust验证、签名者显示名称和签名证书DER SHA-256提取；连接器信任复核复用同一适配器，避免两套证书指针读取逻辑漂移。
- `src-tauri/src/ai_sidecar_trust.rs`只接受同一目录中的固定`yuanyuan-reminder.exe`与`yuanyuan-ai.exe`。两者必须同时通过链验证、精确发布者和同一冻结证书SHA-256。
- 验证前拒绝空文件和重解析文件。两个已验证文件句柄在整个监督配置生命周期内保留，并仅共享读取，阻止其他进程在首次启动或熔断重启前写入、删除或替换路径。
- `src-tauri/src/ai_supervisor.rs`的产品入口只接受`TrustedAiRelease`；测试专用子进程配置不能流入`start_if_available()`。
- 失败只表现为既有`Unavailable`状态，不向前端、日志或诊断快照返回路径、发布者、证书或具体失败分支。

## 回归证据

5项AI签名启动门测试覆盖：

1. 编译期策略保持显式关闭，相邻文件也不能通过产品入口；
2. 策略只接受完整、规范的大写64位证书SHA-256，未知字段、半开启和异常发布者均关闭失败；
3. 固定同目录文件名、发布者和证书完全匹配时，注入验证器可以形成受信句柄；
4. 受信句柄存活期间真实文件重命名被Windows共享模式拒绝，释放后才允许；
5. 签名无效、验证器不可用、发布者不同和证书不同分别关闭失败。

既有16项来源工具信任回归在抽取共享WinTrust适配器后全部通过。共享适配器加入签名证书DER SHA-256提取后，本机受管理Codex的8线程真实签名/包身份适配测试再次连续运行20轮，共160次验证全部通过。加入Support Sort源码隐私门、真实AI子进程金丝雀、稳定核心日志金丝雀、未注册面板门、非默认PID复用执行器、AI崩溃隐私闸门和正文预读闸门后，完整默认Rust回归为524项，其中521项通过、3项环境门按设计忽略；全特性为541项通过、另3项忽略。`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`npm.cmd run verify`、release构建、Tauri/NSIS构建和发布预检均通过。
