# 圆圆 1.5.8 情境装扮可开发方案（V2）

状态：已按本文件完成实现，并已完成最终安装器绑定的离线 Windows Sandbox 干净安装、升级和安全回退 E2E；最终公开发布仍以签名、外部安全软件和具名人工 Windows 体验验收为准。  
基线：1.5.7；目标版本：1.5.8。

## 1. 最终产品契约

- 语义场景为 `none | spa | meal | hydration | warmup | study | night | work`；`work` 另带 `fresh | transition | fatigued`。
- `CompanionExpressionSnapshot` 使用 schema v2。Rust 是展示优先级与当前语义场景的唯一权威；React 不从提醒、专注、学习或任务快照重新推导优先级。
- 展示顺序固定为：Windows 锁屏认证、到期提醒/`waiting_user`、用户主动交互、活动提醒、专注/学习、可信运行任务、水疗、睡眠/普通待机。同层提醒固定为补水、用餐、其他、`waiting_user`。
- `sceneWardrobeMode` 提供 `off | reminders_only | full`，默认 `full`。旧设置缺失字段时使用默认值；关闭装扮时保持 1.5.7 视觉语义。
- 运行时只使用本地编译资源与内存/SQLite 状态，不增加网络请求、遥测或内容上传。

## 2. 状态与交互

- 水疗会话只存于进程内存，提供查询、5/10/20 分钟开始、提前停止和 `scene-rest-updated` 事件；应用重启不会恢复。
- 开始专注、学习或手动睡眠会停止水疗；提醒和短交互只抢占显示，水疗仍有效时可重新呈现。
- 专注期间允许短交互且计时继续；提醒有效时拒绝低优先级交互。`waiting_user` 可抢占专注，普通运行任务不可。
- 工作疲劳点取 `clamp(activityIntervalMinutes, 20, 60)`；80% 进入过渡，100% 进入疲劳。仅活动专注和可信运行任务累计；真实休息或完成热身后从内存恢复点重新累计。

## 3. 动画控制与回退

- `scene-atlas.webp` 固定为 1536×3744、8×18；行顺序见 `PET_PACK_SPEC.md`。
- 所有新动作登记在统一 `animations` 注册表，`SpriteSheetName` 增加 `scene`，每个动作都有 `staticFrame`。
- 水疗和夜间执行 enter→loop→exit；用餐、补水和热身执行 alert→loop；工作执行 focus、fatigue-enter、fatigue-loop、recover；学习好奇动作只由既有学习交互触发。
- 高优先级场景立即取消未完成的一次性动作；场景结束后重新读取 Rust 语义快照，不恢复被打断的中间帧。
- 场景图集缺失、损坏或解码失败时仅回退视觉动作，提醒及其完成/稍后/跳过操作保持可用。动画关闭和减少动态直接显示稳定帧。

## 4. 数据库与用餐提醒

- 主数据库最大 schema 为 13。迁移 013 在事务内重建 `reminders` 类别约束和 `occurrences` 外键表，保留字段、数据、唯一约束及索引，并在打开数据库后执行 `foreign_key_check`。
- 无学习构建允许 11→13；学习构建允许 12→13；迁移失败回滚到完整旧 schema。
- `meal` 已贯通 Rust/TypeScript 类型、校验、表单、一次/间隔/每天/每周调度、历史筛选、窗口提醒与系统通知；不推断地点、饮食或时间。
- occurrence 解决事件固定携带 `{ occurrenceId, category, action }`，其中 `action` 为 `complete | snooze | skip`。

## 5. 无障碍、资源和验收

- 每个语义状态使用固定可访问名称，只在真实状态变化时更新 live region，循环帧不重复播报。
- 电脑和咖啡杯只来自无文字、无品牌且 `aria-hidden` 的界面道具层，并和既有电脑道具去重；穿戴物绘入图集。
- 资源装配会检查 18×8 单元、透明角、边距、隐藏 RGB 和静态帧，生成接触表及代表性循环 GIF；生成源和第三方参考不进入发行资源。
- 自动测试覆盖优先级、抢占恢复、工作阶段边界、休息会话、三个装扮模式、18 行映射、资源失败、013 升级/回滚和外键完整性。最终门为 `npm.cmd run verify`、Rust 全量测试和 Tauri 生产构建。
- Windows Sandbox 安装验收运行最终 NSIS 安装主程序，覆盖离线提醒、窗口交互、备份恢复、重启持久化、默认卸载保留和显式删除；升级验收从明确的 pre-013/schema 12 当前产品源码构建 1.5.7 测试基线，要求基线启动后仍为 12、1.5.8 首次启动后为 13，并验证回装 1.5.7 与恢复旧库后仍可启动。基线元数据保留原始源码版本和仅版本资源覆盖事实，不能作为历史正式 1.5.7 发布证明。
