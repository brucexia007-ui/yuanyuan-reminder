# 圆圆提醒工具 v1.3.1 修复方案

## 目标

修复 v1.3.0 E2E 回归中发现的数据、提醒交互和活动计时问题，并建立能覆盖这些问题的自动化验收。

## 修复范围

### 1. 喝水完成与今日计数一致

- 点击喝水提醒的“完成”时，事务性写入一条喝水记录。
- 重复点击同一条提醒不得重复计数。
- 点击“记录一杯”只处理一条最早的待处理喝水提醒。
- 同一喝水计划同一时间只保留一条待处理记录，后续周期不继续堆积。

验收：

- 一条喝水提醒从待处理变为完成后，今日喝水立即加一。
- 重复完成不增加第二杯。
- 一个小时内存在未处理提醒时，不生成第二张待处理喝水卡。

### 2. 按 Windows 本地日期统计

- “今日喝水”和今日已处理事项使用本地零点到下一本地零点的 UTC 边界查询。
- 今日面板跨过本地零点后自动刷新。
- 历史记录仍保留完整时间戳，不修改既有数据。

验收：

- 北京时间 00:00–08:00 不混入前一天记录。
- 面板持续打开跨过零点后，无需手动刷新即可显示新一天数据。

### 3. 提醒气泡直接处理

- 强提醒气泡提供“完成”“10 分钟后”“跳过”三个明确按钮。
- 装饰性勾号不再伪装成可点击的完成按钮。
- 操作后立即关闭当前提醒并恢复圆圆状态。
- Windows 系统通知保留为提示入口；桌面端不再依赖当前通知组件不支持的动作按钮。

验收：

- 不打开任务面板即可处理喝水、工作和活动提醒。
- 三种操作均更新待办、历史记录和圆圆动画状态。

### 4. 活动计时改为“累计有效使用”

- 少于 5 分钟的无输入时间继续视为正常使用。
- 5–10 分钟无输入时暂停累计，不清零。
- 连续离开 10 分钟视为真正休息并重置累计。
- 关闭活动提醒、离开活动时段或进入休息专注时重置。
- 每分钟保存一次累计进度，程序重启后继续累计。
- 增加触发、暂停和重置的测试覆盖。

验收：

- 50 分钟有效使用、短暂停顿、再使用 10 分钟能够触发提醒。
- 真正离开电脑 10 分钟后重新累计。
- 喝水与活动同时待提醒时仍然先喝水、后活动。

### 5. 自动化与发布门槛

- 增加本地日界线、喝水完成计数、防重复提醒和活动暂停/重置测试。
- 浏览器演示数据支持完成、稍后、跳过和记录喝水，避免交互测试成为无效点击。
- 完成前必须通过：
  - `npm.cmd run verify`
  - `cargo test`
  - 提醒气泡和设置界面 E2E
  - `npm.cmd run tauri build`

## 发布策略

- 版本号升级为 `1.3.1`。
- 保留现有数据库结构和历史记录，升级不清空用户数据。
- 生成安装版与便携版，并在正式版数据上只做只读核验。
