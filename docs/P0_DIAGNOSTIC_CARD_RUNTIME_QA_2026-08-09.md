# P0 诊断卡真实窗口验收（2026-08-09）

## 结论

诊断卡已在当前 Windows 桌面的 144 DPI（150%）环境完成真实 Tauri 正向验收。窗口物理尺寸为 607×943，折算逻辑尺寸为 404.7×628.7，符合 390—420×610—650 的窄面板门限；初始卡片和“保存前确认”预览均未出现横向裁切、遮挡或不可读文字。

键盘焦点闭环为“查看诊断快照内容 → 选择保存位置 → 取消 → 查看诊断快照内容”。预览打开后焦点进入主操作，取消后返回原入口；随后再次打开预览并通过同一按钮唤起 Windows 原生保存窗口。原生窗口被真实观察、确认并关闭，隔离目录中只生成一份 JSON。清理诊断数据的二次确认也使用同一确定性焦点规则。状态变化使用礼貌实时区，保存期间暴露忙碌状态，强制颜色模式保留卡片边界和焦点环。

本次只关闭当前 150% DPI 的真实窗口、键盘与自动无障碍树验收，不关闭 100%、125%、200% DPI、高对比度实拍、文本缩放或 Narrator 人工听读。

## 隔离与隐私

- 使用非默认 `runtime-qa` 的 `diagnostics` 配置，只返回固定合成脱敏元数据，并在原生窗口选择的隔离目录中生成一份诊断 JSON；不接入真实任务、路径、提示词、倾诉或凭据；
- 应用启动前铺设不可激活的中性灰色隐私背景，采图时仅把诊断面板临时置于该背景之上；两张截图均经人工复核，没有桌面或其他应用内容；
- Windows UI Automation 只查找固定名称的标题、状态、预览区和按钮，并用 Enter/Tab 完成真实键盘链；
- 正式用户目录新增写入为 0，Application Error 为 0，应用与隐私背景均受控退出，带标记隔离根已删除；
- 应用没有在自有诊断目录创建副本，也未向 WebView 返回用户选择的路径或自动上传；采集器只为离线复验复制固定合成导出文件到证据目录；
- 失败调试轮的不完整报告、截图和导出证据均按精确文件名清理，只保留最终报告、两张截图与一份合成导出 JSON。

## 自动门禁

`verify_diagnostic_card_evidence.mjs`会重新绑定主程序、夹具、采集脚本和隐私背景脚本的 SHA-256，并独立检查：

- 报告 Schema 与字段集合无漂移；
- DPI、物理/逻辑尺寸换算和四组关键无障碍边界均一致且位于窗口内；
- 键盘焦点、隐私、零正式写入、Application Error、退出与清理全部通过；
- 两张 PNG 位于唯一证据目录，名称、哈希和尺寸与报告一致；
- 图像具有足够的颜色和亮度变化，旧的纯灰背景截图不能冒充通过证据；
- 合成导出 JSON 的文件名、字节数和SHA-256与报告一致；字段集合、固定枚举、队列数字和诊断计数逐项复算；
- 最终导出敏感匹配为0，扫描版本1执行4项检查；路径不回传、无应用内副本、无自动上传三项必须全部为`false`。

7 项篡改回归覆盖 UTF-8 BOM、来源过期、未知字段、DPI 虚拟化、控件越界、焦点/隐私/隔离/退出失败、截图失效/错尺寸/灰屏，以及敏感、陈旧或乐观伪造的导出文件。

## 复现

```powershell
npm.cmd run runtime:qa:build
npm.cmd run runtime:diagnostic-card
npm.cmd run runtime:diagnostic-card:evidence:test
npm.cmd run runtime:diagnostic-card:verify -- --report <绝对报告路径>
```

运行采集需要可交互 Windows 桌面。完整 DPI 矩阵必须分别在 96、120、144、192 DPI 环境取得独立报告，不能用缩放截图或修改报告字段替代。
