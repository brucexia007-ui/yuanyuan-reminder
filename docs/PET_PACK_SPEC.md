# 圆圆提醒宠物包规范

本文定义圆圆提醒 `1.5.9` 使用的宠物素材及成品导入包格式。目标不是让界面“轮播不同照片”，而是让同一只宠物在所有动作里保持身份一致并形成连贯动画。

## 1. 公共几何规则

- 每格：`192 × 208` 像素；
- 每行：8 格，总宽 `1536` 像素；
- 背景：真正透明，透明区域隐藏 RGB 应清零；
- 主体：完整身体不得跨格、裁切或接触外边缘；
- 视觉身份：毛色、脸型、眼睛、鼻子、耳朵、花纹、四肢比例和体态必须保持一致；
- 禁止：场景背景、文字、对话框、投影、光晕、速度线、网格、动作编号和游离特效。

## 2. 标准图集 `spritesheet.webp`

尺寸：`1536 × 2288`，即 8 列 × 11 行。前 9 行是标准动作，后 2 行是 16 个顺时针注视方向。

| 行 | 动作 |
| --- | --- |
| 0 | 安静待机、呼吸和眨眼 |
| 1 | 向屏幕右侧移动 |
| 2 | 向屏幕左侧移动 |
| 3 | 抬爪打招呼 |
| 4 | 跳跃；活动提醒复用这一行形成连续蹦跳 |
| 5 | 失败或失落反馈 |
| 6 | 等待用户处理或确认 |
| 7 | 正在处理任务的专注动作，不是向前跑 |
| 8 | 检查或回顾动作 |
| 9 | 注视 000°、022.5°、045°、067.5°、090°、112.5°、135°、157.5° |
| 10 | 注视 180°、202.5°、225°、247.5°、270°、292.5°、315°、337.5° |

方向使用屏幕坐标：000° 向上，090° 向右，180° 向下，270° 向左。四个主方向必须一眼可辨，不能只靠极小的瞳孔移动。

## 3. 睡眠图集 `sleep-atlas.webp`

尺寸：`1536 × 624`，8 列 × 3 行。

| 行 | 动作 |
| --- | --- |
| 0 | 从清醒进入睡姿 |
| 1 | 熟睡呼吸循环 |
| 2 | 从睡姿醒来 |

进入睡眠和醒来应是可逆的姿态变化；循环帧需保持身体基线稳定。

## 4. 生活与互动图集 `life-atlas.webp`

尺寸：`1536 × 4368`，8 列 × 21 行。

| 行 | 动作 |
| --- | --- |
| 0 | 舔爪或洗脸 |
| 1 | 舔胸口 |
| 2 | 舔身体侧面 |
| 3 | 伸懒腰 |
| 4 | 打哈欠 |
| 5 | 喵叫 |
| 6 | 翻肚皮躺下与反向起身 |
| 7 | 专注状态下安静坐卧 |
| 8 | 吃猫粮 |
| 9 | 喝水 |
| 10 | 追随猫条高度和方向 |
| 11 | 基础逗猫动作 |
| 12 | 用头蹭鼠标 |
| 13 | 左右爪扒拉球 |
| 14 | 向目标伸爪 |
| 15 | 抓挠逗猫棒 |
| 16 | 收爪回到坐姿 |
| 17 | 低头叼起球 |
| 18 | 叼球走回 |
| 19 | 放下球 |
| 20 | 双爪拍“屏幕玻璃”的强提醒动作 |

每一行应作为一个连续的 8 帧动作家族生成。不要从不同风格图片中各裁一帧拼接，也不要用程序扭曲一张静态图片伪造动作。

## 5. 情境装扮图集 `scene-atlas.webp`

尺寸：`1536 × 3744`，8 列 × 18 行。穿戴物必须随角色绘入图集；电脑、咖啡杯等界面道具不得绘入图集，由无文字、无品牌、`aria-hidden` 的界面层统一提供。

| 行 | 动作 |
| --- | --- |
| 0—2 | 水疗进入、循环、退出 |
| 3—4 | 用餐提醒、等待 |
| 5—6 | 补水提醒、等待 |
| 7—10 | 工作循环、疲劳进入、疲劳循环、恢复 |
| 11—12 | 热身提醒、循环 |
| 13—14 | 学习循环、好奇反应 |
| 15—17 | 夜间进入、循环、退出 |

每个动画必须在清单中声明 `staticFrame`。关闭动画或系统要求减少动态效果时，运行时直接显示该稳定帧，不依赖一次性动画完成回调。

## 6. 清单文件

运行时清单位于 `public/assets/pet/pet-manifest.json`，定义图集路径、格子尺寸、动作所用行、帧顺序、每帧时长和循环起点。

替换宠物时，优先保留动作名称和调用语义，只在动作实际需要时调整帧序及持续时间。完成后必须执行：

```powershell
npm.cmd run pet:validate
npm.cmd run check
```

## 7. 最低验收条件

- 清单声明的全部图集尺寸和透明通道正确；情境图集必须为 18×8 共 144 个有效单元；
- 标准图集的 8×11 格全部满足结构要求；
- 左右移动方向正确，步态不倒放；
- 16 个注视方向按顺时针形成自然连续环；
- 四个主方向明确，左右不会相反；
- 所有动作保持同一宠物身份；
- 动画没有尺寸跳变、基线跳动、裁切、残影或背景色边；
- `npm.cmd run verify` 和 Windows 正式构建通过。

### 情境素材装配补充门禁（2026-09-08）

`scripts/build_scene_atlas.py` 在缩放前按完整前景连通姿态提取一行，不能假定生成图的八帧恰好等宽排列。必须恰好八个有效姿态；合并、缺帧、多出显著部件或身体接触源画布边缘时拒绝装配。生成图本身损坏时重做完整动作行，不以输出格边距合格掩盖切断的身体。

局部修复使用 `--base-atlas` 与 `--rows <完整动作行名>`，整格替换并保留未指定行的可见像素。编码采用无损 WebP 的透明 RGB 保留选项，并重新解码实际输出，核对全部 RGBA 像素、144 格边距和隐藏 RGB。源图、解码结果、接触表与真实播放是不同验收层级；同组 enter/loop/exit 还须核对头身比例、服饰及端点姿态，不能分别适配到最大格高后就默认组间一致。

对低伏、蜷睡等循环，支持 `--row-registration <JSON>` 显式引用语义一致的相邻端点。格式为动作行名映射到 `{"referenceFrame":"references/end.png","sourceColumn":0}`，图片路径相对 JSON 所在目录解析；引用必须是有透明边距的 RGBA 192×208 单格。按指定源姿态匹配端点高度、水平中心和底部基线，行内全部原始姿态只缩放一次、使用同一比例；若其他姿态无法完整装入格子，则报错，不裁切、不悄悄缩小。该约束只解决注册问题，不能把错误姿态或身份通过缩放变成合格素材。

开发者在已配置 Pillow/NumPy 的 Python 环境运行独立回归（22 项），无需为普通用户增加运行依赖：

```powershell
python -m unittest discover -s scripts -p test_build_scene_atlas.py -v
```

该检查不替代已有 `npm.cmd run verify`、Rust 全量、生产构建或 Windows 动画实测；候选未替换运行时资源之前，不将素材工具通过计作安装版通过。

## 8. 许可要求

只使用你拥有或获得明确授权的宠物照片和生成素材。不要把第三方社交账号里的宠物照片、图库图片或不明来源模型输出直接提交到公开仓库。每个宠物分支应附带自己的素材许可说明。

## 9. 应用内成品包 V1（1.5.9 新增）

`.yuanyuan-pet` 是 ZIP 文件，根目录必须有以下六个文件，不得包含子目录、链接或其他文件：

| 文件 | 要求 |
| --- | --- |
| `pet-pack.json` | UTF-8 JSON，最多 256 KiB；`schemaVersion: 1`、`spriteVersionNumber: 2`，沿用本文动画名称、行号和循环语义 |
| `spritesheet.webp` | 1536×2288，标准 11 行 |
| `sleep-atlas.webp` | 1536×624，睡眠 3 行 |
| `life-atlas.webp` | 1536×4368，生活互动 21 行 |
| `fallback.png` | 192×208，同一宠物静态形象 |
| `LICENSE.txt` | 非空 UTF-8 素材许可，最多 64 KiB |

可选 `learning-atlas.webp`（1536×832，4 行）和 `scene-atlas.webp`（1536×3744，18 行）。每组必须完整，缺省时清单不得声明该组动画或图集路径；缺省学习时使用本包安静坐姿，缺省装扮时使用本包基础动作，不借用内置圆圆图集。形体布局和接触点仍遵循既有约定，不支持任意体型适配。

清单内图集引用必须是上述固定文件名，`assetLicense` 必须是 `LICENSE.txt`；显示名遵循昵称相同的 1–24 Unicode 字符及控制字符规则。所有动画声明 `staticFrame`（0–7），`frames` 为 1–128 项的 0–7 列索引，`durations` 与帧数相同、每项 10–10000 毫秒，非空 `loopStart` 必须指向有效帧序位置。行数和每格尺寸与内置清单一致。

压缩文件和实际展开内容分别不超过 64 MiB。Rust 在后台逐文件校验真实解码、格式、尺寸、透明通道、可见像素、清单完整性及许可；拒绝加密、重复文件名、路径穿越、外部图集地址和未允许内容。动画身份及动作美观仍需制作方目视验收，导入校验不冒充美术审核。

重复文件名按原始 ZIP 中央目录记录判断，不能依赖会按名称去重的解压库列表；即使重复条目内容相同，或指向同一份压缩数据，也必须在写入解压资源、返回预览前拒绝，并清理临时目录。中央目录字段长度、名称白名单及条目数量均需校验。

安装 ID 为 SHA-256 内容地址：按文件名字节排序，对每项依次写入 UTF-8 文件名、零字节、该文件 SHA-256 小写十六进制、零字节，再求 SHA-256。昵称不参与哈希。正常同内容导入复用，不自动切换；不同内容并存。安装副本位于应用本地数据目录 `pet-packs/<hash>/`。

导入预览使用一次性随机令牌，提交前复核全部文件；取消、失败、重启清理未提交暂存。已安装损坏包可由同内容重新导入修复，未知额外文件阻止自动替换。图片通过仅接受内部 ID 和白名单图片名的 Tauri 本地协议读取，不启动 HTTP 服务，不开放任意路径。运行期再次核对文件哈希。

## 10. 离线打包

素材制作方可用仓库工具打包；普通用户导入不需要 Node.js 或开发工具：

```powershell
npm.cmd run pet:package -- --source <素材目录> --license <素材许可.txt> --output <形象.yuanyuan-pet> --name <原名>
```

目录清单名为 `pet-manifest.json`。工具规范化包内引用，并为旧清单缺少的稳定帧补入首帧列值；它不生成、不修改图片。`--without-learning` / `--without-scene` 可明确排除整组扩展。不覆盖既有输出文件，最终是否可导入以应用校验结果为准。
