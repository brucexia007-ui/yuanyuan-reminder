# P0任务守望台前置实现与验收记录（2026-08-05）

## 结论

任务守望台的“道具可点击、状态可查看、正文不过界”前置链路已经完成，并已在当前150%缩放的真实Tauri窗口中贯通“猫咪道具→任务守望台”。本次使用的是隔离目录中的合成认证事件，不是真实Codex/Claude Code Hook；P1-E09仍未整体完成，也不能据此宣称普通用户已经获得真实任务守望。

## 已实现边界

- 只有带有可信外部任务来源的圆圆道具成为按钮，本地喝水、工作或活动提醒道具不复用该入口；
- 点击外部任务道具打开固定“任务守望”页面；可信状态库不存在时入口不显示，普通用户仍保持原有七项导航；
- 后端沿用只读AI任务摘要适配器，最多读取64项，并只采用最近24小时、时间不在未来的固定状态；
- 聚合在Rust端完成，前端只收到Schema版本、是否可用、总数、需要用户数，以及`来源 + 固定状态 + 数量`；
- 页面明确说明不显示任务标题、项目路径、任务标识或精确活动时间；读取失败局部显示错误，不清空其他提醒模块；
- 开发环境可通过固定聚合夹具检查布局，但该分支受`import.meta.env.DEV`编译门保护，发行边界再次禁止`taskWatchDemo`进入生产文件。

## 隔离正式Tauri运行夹具

- 新增非默认`runtime-qa`编译功能及独立`yuanyuan-task-watch-fixture`二进制，默认正式构建不会编译或打包它；发行边界同时拒绝Tauri资源或辅助进程声明包含`runtime-qa`或该夹具名；
- 夹具只接受绝对路径、名称以`yuanyuan-runtime-qa-`开头的叶子目录，并要求精确标记文件`.yuanyuan-runtime-qa-v1`；已存在但无标记的目录、重解析目录和不安全父目录均关闭失败；
- 运行时使用独立应用标识，并隔离提醒库、AI任务库和共享的QA WebView数据目录，不读取或写入正式用户目录；共享目录与正式Tauri一样复用WebView环境，避免验收模式人为创建两套进程群；本次运行开始后，正式用户数据目录新增写入为0；
- 夹具使用固定测试密钥生成8条合成认证事件，经真实事件验签、任务存储、只读摘要、表达导演、Tauri命令和React页面完整流转；覆盖Codex/Claude Code的运行、等待用户、成功、失败和疑似停住状态；
- 固定测试密钥、合成事件和运行入口只存在于`runtime-qa`编译分支。它证明真实桌面运行链路，不证明来源工具身份、真实Hook授权或生产密钥生命周期。
