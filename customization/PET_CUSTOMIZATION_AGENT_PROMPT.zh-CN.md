# 宠物定制智能体执行合同

本合同适用于 Codex、Kimi Code、WorkBuddy，以及其他能联网获取 GitHub 仓库、读取附件、读写工作区并执行命令，且具备参考图生成或编辑能力的 Coding 工具。用户提供宠物照片、宠物名、性格和照片使用授权，并在动作生成前确认主形象；不得要求用户预先下载项目、运行命令、安装依赖、手工编辑 JSON、填写 identifier，或自行判断品种、性别。默认摄影写实，用户明确指定其他风格时遵从其选择。

## 零源码引导

1. 用户电脑上可能完全没有本项目。智能体必须自行创建工作目录，并从 `https://github.com/brucexia007-ui/yuanyuan-reminder` 获取默认分支的最新完整 Git 工作副本。
2. 优先使用工具自身的 GitHub 导入/克隆能力；否则由智能体自行使用 Git。若缺少 Git 或构建依赖，由智能体在权限范围内准备；需要系统授权时只请求必要授权，不得要求用户复制或执行命令。
3. 执行任何仓库脚本前，核对远端为上述无凭据 HTTPS 地址、工作树位于新建目录内，并确认根目录存在 `AGENTS.md`、`package.json`、`src-tauri/` 和本合同。来源不一致时停止，不得继续运行仓库内容。
4. 网络、GitHub 访问或必要权限确实不可用时，说明具体阻塞；不得把“用户手动下载、解压或运行命令”作为正常流程。

## 共用的身份、风格与主形象确认

两条路线都必须先阅读 `docs/CUSTOMIZE_YOUR_PET.md`、`docs/PET_PACK_SPEC.md` 和素材许可，再执行以下流程。原始照片、身份锁、确认记录和私有对照仅放在被 Git 忽略的 `work/`；以 [身份锁](../pet-template/identity-lock.template.md) 和 [写实与动作验收模板](../pet-template/realism-review.template.md) 记录依据。

1. 实际查看全部照片，区分身份照片与风格参考。保留真实年龄感、脸型、眼睛大小/间距、口鼻长度、头身比例、四肢、体态、毛流、花纹和不对称特征。照片中本来存在的圆眼、短鼻不得“纠正”；圆圆、饺饺只参考质感和动作，不能复制身份。
2. 写实模式下保留细小杂毛、胡须、自然眼部反光及身体自身明暗，使用一致的柔和光照和透明背景。避免幼态化、卡通大眼、玩偶形体、塑料毛发及风格化 3D 吉祥物效果。性格通过动作体现，不改变五官。用户选择其他风格时记录该选择，按约定风格验收，不把写实禁项机械套用到用户主动要求的卡通效果。
3. 以真实照片为图像输入，先制作完整身体主形象；展示私有原照对照和桌面尺寸预览，请用户确认身份与风格。确认前不生成动作，无回复不视为确认。主形象失败须回到原照修正，不在失败图上继续衍生。更换已确认主形象须重新确认，其他步骤自行检查推进。
4. 确认后先试做待机呼吸/眨眼、转头、行走，检查自然度、身份一致和连续播放，通过后再批量制作。每次生成实际传入原照与已确认主形象；不能只输入品种文字，或仅沿用上一轮生成图。完整动作行逐行生成，再确定性装配，不依赖一次生成全部大图集。
5. 保留关节弯曲、落脚、重心转移和自然起落，避免频繁歪头、拟人挤眼微笑、机械摆动或橡皮式拉伸。待机克制，跳跃、强提醒及互动仍须保持原功能语义；不得用静态图片变换冒充关节动作。既有素材只有符合当前身份、已选风格和动作要求才能复用；失败时重做相关完整动作行。
6. 按模板分别记录结构、视觉、用户确认和原生播放。逐行检查毛发/花纹闪烁、比例漂移、基线与循环接缝，并检查实际显示尺寸及深浅背景。模板是人工制作记录，不是新增包内文件、程序门禁或风格枚举；不得把 `photorealistic` 写入不支持它的旧 schema。独立应用旧请求保持合法枚举，具体写实要求记录在身份说明与复核记录中。

缺少参考图输入能力或反复修正仍不能保持身份时，说明具体能力限制，不自行降级为卡通并宣称完成。提示词与工具名称不构成效果保证。

## 普通宠物包路线（默认）

复用当前圆圆主程序，不执行品牌、应用图标或数据库路径替换。先在被忽略的工作目录准备有许可的图集，按宠物包规范完成身份与动作验证，再由智能体执行 `npm.cmd --silent run customize:auto -- --source <素材目录> --license <许可文件> --name <宠物名>`；用户绝不能被要求执行它。保存返回的 runId/resumeCommand，恢复时重新校验素材和许可。该入口仅输出候选包，声明的兼容版本必须另做真实导入、播放和重启验收。

- 交付标准 11 行、睡眠 3 行、生活互动 21 行、`fallback.png` 和独立许可；按本次定制提示词补齐学习 4 行。协议允许省略完整学习/情境组时，明确记录范围并使用本宠物的基础动作回退，不能引用内置圆圆素材。
- 遵循包规范的固定文件白名单。身份锁、照片、确认记录和 QA 报告不放入 `.yuanyuan-pet`；报告作为单独私有交付物提供。
- 默认路线不执行下方独立应用的 `customize:complete-step`、`customize:verify`、`customize:package` 或图标替换流程。包工具只接收已制作素材，不会生成图片。
- 最终交付 `.yuanyuan-pet`、校验和、许可、独立验收报告和交付清单。原生导入、动作、互动、切换、重启与兼容版本未验收时标记候选及未完成项；不得将结构通过或候选包生成等同于完成验收。

## 独立应用兼容路线（仅在用户明确要求时）

以下步骤仅用于独立应用；其中原来的 `customize:auto --photos` 入口改用 `customize:standalone --photos`。不要在普通宠物包任务中执行这些品牌替换步骤。

### 首次接手

1. 完整读取 `AGENTS.md`、`docs/PET_PACK_SPEC.md`、`ASSETS_LICENSE.md` 和本合同；以仓库自己的说明为准，不依赖用户另行提供文件。
2. 从当前消息附件中定位全部照片。若工具必须整理附件，只能复制到被 Git 忽略的 `work/`；不得把照片放入 `public/`、Tauri resources、源码、提交或日志。
3. 智能体自己运行内部入口；用户绝不能被要求执行它：

   ```powershell
   npm.cmd --silent run customize:standalone -- --photos "<附件文件或私有目录>" --name "<宠物名>" --personality "<性格>"
   ```

   多个分散文件可重复传入 `--photos`。必须保留 `--silent`，避免 npm 回显私人路径。
4. 读取输出中的 `runId`、`handoffPath` 和 `resumeCommand`，再读取当次 `agent-handoff.json`、请求快照、品牌草稿与身份锁草稿。此后持续执行 `resumeCommand`，直到所有步骤与交付物完成。
5. 根据全部照片补全九项视觉身份、保持/避免规则，并推断品种和性别。无法可靠判断的非关键字段保留 `unknown / 由参考照片识别 / auto`，不得因此反问用户。

### 独立应用必须自动完成

- 依照 `AGENTS.md`、`docs/PET_PACK_SPEC.md` 和 `hatch-pet`（可用时）生成标准 8×11 v2 图集；不得用静态图抖动、缩放或旋转伪造动作。
- 生成睡眠 3 行、生活互动 21 行、学习表达 4 行、五张静态回退图和四个 Windows 图标。
- 保持猫条、八方向逗猫、头部摸摸、完整扔球、提醒优先级和专注安静状态机语义。
- 逐步使用 `customize:complete-step` 登记所有必需产物；视觉语义模板不得保留 `pending`。
- 执行 `customize:verify` 和 `customize:package`，最终交付安装版、便携版、SHA-256、QA 联系表和交付清单。

独立应用遇到可恢复失败时应自行修复并再次执行 `customize:resume`。等待主形象确认、缺少必要图片能力、Windows 构建环境或照片授权时，如实报告待办或阻塞；无回复不能越过主形象确认。不得把外部工具名称写入最终宠物包，三个工具的输入、产物与验收合同完全相同。

## 隐私和报告边界

- 私人照片路径只从本地附件或独立应用当次 `request.json` 读取；面向用户的消息只报告照片数量，不复述路径或文件名。主形象对照只在本次私有会话展示。
- 原始照片、其完整字节、EXIF 信息和绝对路径不得进入 Git 可见文件、正式产物或测试输出。
- 最终报告按所选路线给出成品、校验和、许可、QA 证据、交付清单和验收结论的位置。缺少生成实验或原生实测时不得虚构通过；公开仓库只提交空白模板，不提交填写后的私有记录。

## 私人素材工程及后续修复交付

两条制作路线均按[私人素材工程清单](../pet-template/source-project.template.md)归档：已确认主形象、可获得的高清完整动作源图、身份锁、装配参数、工具及源码版本、素材许可和验收记录。默认排除原始照片、私人绝对路径、会话记录及应用数据；填写后的记录留在被忽略的 `work/`，独立交付，不加入 `.yuanyuan-pet`。旧包缺少高清源图时如实列缺，不伪造可完整重建的工程。

向用户提供[宠物包修复提示词](../AI_PET_REPAIR_PROMPT.md)。修复在原包副本中按[离线工具工作流](../docs/PET_REPAIR_WORKFLOW.md)执行，不重生成合格动作；仅改变主形象时重新确认。主程序问题交付复现报告。
