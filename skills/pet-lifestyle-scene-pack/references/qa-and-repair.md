# 质量核验与修复

生成后使用 `view_image` 检查原图，不只看缩略图。每张图都要通过全局检查和对应场景检查，才可计入交付。

## 全局门槛

- 单张独立 3:4 竖图，不能是拼图、多面板、截图或横图。
- 只有一只宠物；物种、脸型、眼色、口鼻、耳型、毛色花纹、体态和尾巴与身份锁定一致。
- 宠物的目光、耳位、尾势、姿态、动作能体现用户提供的性格，并在不同场景中有自然变化。
- 场景参考图的白猫身份、固定表情和饺饺特有性格不得泄漏给目标猫或狗。
- 真实猫爪或狗爪，无人手、人类手指、多余、缺失、融合或悬空的肢体；只有真实存在的尾巴。
- 道具与爪子、身体、地面和前后景关系合理，没有穿模或漂浮。
- 柔和写实粉彩写真、真实毛发与材质、奶油色外边框、大圆角、柔光；无拼贴感。
- 无可读文字、乱码界面、Logo、商标、水印或签名。
- 用户关闭蝴蝶结或工牌后，所有场景都不得偷偷恢复；开启时样式跨场景一致，工牌不含名字或文字。
- 不使用“公宠物一定深色、母宠物一定粉色”等性别或品种刻板表达。

## 易错项专项检查

- `01-music-phone`：屏幕朝宠物、背面朝观众；双爪持机，未抬手挥舞。
- `02-spa-mask`：面膜独立覆盖毛发，鼻口孔位正确，两片黄瓜位于眼部。
- `03-travel-suitcase`：爪子、把手、箱杆、箱体和轮子形成连续受力关系。
- `04-badminton`：握拍前肢伸直；网在前景并达到胸部高度；拍、球、网不互相穿透。
- `05-swimming`：泳镜对准眼睛，两只前爪抓住浮板，身体确实位于水中。
- `06-hydration`：只有两只侧杯；每根软管都有明确起点和终点。
- `07-online-duty`：麦克风靠近嘴边，按钮确实在爪下，眼镜和耳机不穿模。
- `08-sleep`：眼罩、双眼、耳朵关系合理，毯子下身体轮廓连续。
- `09-study`：书本和页面透视正确，无乱码，前爪没有穿进书页。
- `10-exercise`：只有一只前爪高举，举臂伸直且连接肩部，爪垫不是人掌。
- `11-weekend-off-duty`：电脑明确合上，姿态表达休息而非工作，不用文字传达“勿扰”。
- `12-work-fatigued`：托脸的是连接身体的真实前爪；电脑不遮住主要身份特征。
- `13-work-focused`：正脸适合身份确认；前爪与键盘接触自然，姿态专注而不疲惫。

## 修复规则

1. 身份整体漂移、物种错误或身体结构严重错误：重新生成该场景，并再次附上原始身份照片。
2. 单一道具方向、遮挡或小范围结构错误：编辑失败图，只描述一个需要修复的缺陷，并要求保留已通过区域。
3. 每张最多两轮自动修复。每轮之后重新执行完整检查，防止修复引入新肢体、花纹漂移或配饰回归。
4. 两轮仍未通过：停止该场景，保留已通过图片并向用户说明具体未解决项；不要把失败图冒充最终结果。

## 输出和机械验证

本地可写时，将完整套装保存为 `01-music-phone.png` 至 `13-work-focused.png`。运行：

```powershell
python scripts/validate_pack.py <输出目录>
```

只生成或重做部分场景时运行：

```powershell
python scripts/validate_pack.py <输出目录> --allow-subset
```

包含自定义场景时运行：

```powershell
python scripts/validate_pack.py <输出目录> --allow-subset --allow-custom
```

检查内置参考资产及其授权哈希：

```powershell
python scripts/validate_pack.py assets/reference-scenes --check-reference-hashes
```

机械验证只检查文件、PNG、尺寸比例和重复哈希，不能替代视觉检查。
